# efeengine-core

The core library of the efeengine game engine. It provides the `Engine` type (window, logger, wgpu graphics context, a `hecs::World` with built-in components, a type registry of script-visible layouts, deferred world `Commands`, per-frame input state, resources and a system schedule), an engine configuration (`EngineConfig`) and a one-shot startup configuration (`StartupConfig`), an engine-owned message queue plus a global one for JS and workers, a platform-neutral input system (keyboard, mouse, touch, text, window events), a fixed-timestep frame loop, a headless mode for tests, a cross-platform, runtime-resizable thread pool (native threads or wasm Web Workers) and the `prelude` that games import. A game is a small crate that depends on this crate and uses the `#[main]` attribute re-exported from `efeengine-macros`. Rendering is split: the engine owns the GPU and builds a plain-data `RenderFrame` each frame, the frame is split into `Frame2D` / `Frame3D` and drawn by a `Renderer2D` (default `SpriteRenderer`) and an optional `Renderer3D`, or by one `CustomRenderer` (see `docs/RENDERING.md`, `docs/RENDERER_PLAN.md`). The code is early-stage and a few modules are stubs (see the last section). The design the input system and loop were built from is `docs/design-io-and-loop.md` (section 11 lists where the code deviates).

## Main concepts

### Engine and its loop (`src/engine.rs`)
`Engine` owns `windows: GameWindowManager`, a private `lifecycle: Lifecycle` (`Created`, `Running`, `Paused`, `ShuttingDown`, `Terminated`; `lifecycle()`, `is_running()` and `is_paused()` read it), `logger: Box<dyn Logger>`, private `renderer: Renderers`, `overlays: Vec<Box<dyn RenderOverlay>>`, `input_filters: Vec<Box<dyn InputFilter>>` and `gpu: Option<GpuContext>` (declared before `windows` so the surface drops first), `state: EngineState`, plus private bookkeeping: the `EngineConfig`, the `EventRegistry`, the `Schedule`, the `Commands` buffer, a reusable input-event buffer, the frame-rate cap and its own message queue (`msg_tx` / `msg_rx`). `EngineState` holds `world: hecs::World`, `types: TypeRegistry` (Transform, Velocity, MeshHandle, TextureHandle, Camera, Sprite, Visibility, Parent and GlobalTransform are registered in `with_config`; `Children` and `Name` are Rust-only), `window: WindowState { size, scale_factor, focused }` (physical-pixel size, DPI scale, focus; kept up to date from window events, initial value `(0,0)` / `1.0` / `true` until the first events arrive), `input: InputState`, `time: Time` and `resources: Resources`.

`Engine::new(title)` is `with_config(EngineConfig::new(title))`; both return `Result<Engine, EngineError>`. `with_config` merges the startup config into the `EngineConfig` (it fills `threads` and `canvas_id` where they are `None`; reading the startup config also locks it, see below), validates it (`fixed_dt > 0`, non-zero window size unless headless, `threads != 0`) and then, unless `headless`: (a) calls `init_log_crate_logger()`, which installs a `log` crate backend (`env_logger` on native, `console_log` on wasm; harmless if called twice) so wgpu validation errors and config warnings are visible, (b) starts the global thread pool (`init_global_pool(n)` if `threads` is set, otherwise `init_global_pool_auto()`), (c) on wasm installs `console_error_panic_hook`. It then creates the window manager (SDL window on native, `WebWindow` on wasm, `HeadlessWindow` when headless; window creation errors come back as `EngineError::Window`), the logger (`NewDefaultLogger`, or `LogCrateLogger` when headless, because the native default logger calls SDL), `EngineState` and the engine's own message queue. Status starts as `Uninitialized` and only messages and commands move it out of that state.

Systems and data: `add_system(stage, f)` registers a `FnMut(&mut Ctx)` in a `Stage` (`Startup`, `PreUpdate`, `FixedUpdate`, `Update`, `PostUpdate`, `RenderExtract`, `Shutdown`; sorted by `(order, registration index)` within a stage; `add_system` / `add_par_system` return a `SystemEntry` (`.order(n)`, `.name(..)`; default `order::USER`), so calls can no longer be chained). `Engine::add_plugin(impl Plugin) -> Result<&mut Self, PluginError>` runs `Plugin::build` with every system added meanwhile tagged with the plugin's name (nested plugins work; duplicates and missing dependencies are errors); plugins register components with `register_component_owned::<T>(self.name())` and depend on `efeengine_core` only, using its `hecs` / `glam` re-exports. Introspection: `system_names(stage)`, `system_owners(stage)`, `plugins()`, `has_plugin(name)`. In debug builds, a re-sort logs (`log::debug!`) when systems of different plugins share an order number and conflict. Tests: `tests/order.rs`. `add_event::<T>()` registers an event type (it is also registered on first `send`). `insert_resource`, `resources()`, `resources_mut()`, `time()`, `input()`, `config()`, `sender()` (a `flume::Sender<Message>` for this engine's own queue), `inject(InputEvent)` (queue an input event for the next frame; tests and headless mode), `is_running()`, `world()` / `world_mut()`, `change_tick()`, `track_changes::<T>()` (change detection; `Transform` and `GlobalTransform` are tracked; the prelude re-exports `Tick`, `Mut`, `Changed`, `Added`, `ComponentTicks`; `Engine::apply_commands` bumps the tick once per apply and `frame` calls `maybe_check_change_ticks`), `types()`, `register_component::<T>() -> Result<u32, TypeError>` and `register_struct(StructDesc) -> Result<u32, TypeError>` are the other accessors.

`Engine::frame(now_secs)` is the one shared frame function (any monotonic clock, in seconds). In order:
1. `time.advance(now)`: delta from the previous `now` (the first frame has delta 0), clamped to 0.25 s, added to the fixed-step accumulator; it returns the number of fixed steps (at most 8; a larger backlog is dropped).
2. `events.update_all()`: every `Events<T>` swaps its pending buffer into the readable one.
3. `input.begin_frame()`, then `windows.poll_events(&mut buf)` (injected events first, then the backend's), then for each event the engine handles window events (`Resized` updates `state.window.size` and reconfigures the surface via `resize_surface`, a 0x0 size suspends the `GpuContext` (no surface acquire or reconfigure) until the next non-zero size, and it is ignored when there is no graphics yet; `ScaleFactorChanged` and `Focused` update `state.window`; `CloseRequested` logs and requests shutdown) and `input.apply(ev)`. Input is polled and applied in the same frame it is used.
4. `drain_messages()`: drain the engine's own queue and, if the engine is not headless, the global queue; handle the control messages (status, title, thread count, frame rate, log, ...) and put all of them into the readable buffer of `Events<Message>`, so systems can read them with `cx.events::<Message>()` in the same frame.
5. `Startup` (first frame only), `PreUpdate`, `FixedUpdate` once per accumulated step (`time.delta()` equals `fixed_delta()` inside it), `Update`, `PostUpdate`, `RenderExtract`. After each stage the engine applies the `Commands` the systems queued: first the world ops in order (`Commands::apply`), then the control requests (`quit`, `set_title`, `set_frame_rate`, `set_cursor_visible`, `set_cursor_grab`, `set_fullscreen`, `set_text_input`).
6. If the GPU exists (never headless), acquire the surface, draw the passes (`Renderer3D::render` if a 3D camera is active, then `Renderer2D::render`, or `CustomRenderer::render(&Gpu, &view, &RenderFrame)` alone), then each `RenderOverlay::render(&Gpu, &target_view)` in add order, present. Overlays get `init` with the renderer (or at `add_render_overlay` if the GPU is up) and `resize` after every surface reconfigure and every `ScaleFactorChanged` that changes `Gpu::scale_factor`. `Outdated` / `Lost` reconfigure the surface (next frame renders), `Timeout` skips, suboptimal reconfigures after present; other errors are logged. A frame that was not drawn puts its texture changes back, so the renderer still sees them once. Built-in systems registered by `with_config`: `velocity_system` (`FixedUpdate`), `propagate_transforms` (`PostUpdate`), `render_extract` (`RenderExtract`).
7. If a shutdown was requested this frame (`Kill`, `quit`, close request), `Shutdown` runs once and the engine becomes `Terminated`. Later `frame` calls are no-ops. A paused frame ends after step 4 (and `Startup`, on the very first frame).

`tick()` reads the platform clock (native: `Instant` since engine creation; wasm: `performance.now()`) and calls `frame`. `run_frames(n, dt)` drives `frame` with a synthetic clock and stops early when the engine is killed; the first frame has delta 0, so n frames at `dt == fixed_dt` run n-1 fixed steps.

`game_loop(self)` dispatches by target:
- native: `sdl_loop()` blocks on `init_graphics()` (via `pollster`; skipped when headless), then loops `tick()` and a frame limiter that sleeps up to `1 / max_fps` (default 60; `Message::SetFrameRate` or `EngineCommands::set_frame_rate` changes it, `<= 0` = uncapped). It breaks once the engine is no longer running (`Kill`; a paused engine keeps looping and sleeps ~16 ms per frame when uncapped), so `game_loop` returns and the engine is dropped normally (no `process::exit`). Status `Running` has no effect on whether ticks happen (ticks always run).
- wasm: `wasm_loop_start()` runs `init_graphics()` inside `wasm_bindgen_futures::spawn_local` (the browser cannot block on async GPU init) and only then starts the `requestAnimationFrame` loop (`wasm_run_frames`, engine in `Rc<RefCell<..>>`), which calls `frame(timestamp_ms / 1000)` until the engine is killed (also while paused). If graphics init fails the error is logged and the loop still runs without rendering.

`init_graphics()` calls `GpuContext::new(&windows)` (`Result<_, String>`); on success it calls the renderers' `init` and stores the context in `gpu`, on error it logs and leaves `gpu` `None` (the engine ticks without rendering).

### Time, resources, events, schedule (`time.rs`, `resources.rs`, `events.rs`, `schedule.rs`)
- `Time`: `delta()` / `delta_f64()` (clamped to `MAX_DELTA` = 0.25 s; the fixed step inside `FixedUpdate`), `fixed_delta()`, `elapsed()` (sum of clamped deltas), `frame()`, `alpha()` (accumulator / fixed step, for interpolation). The engine drives it through `advance`, `set_in_fixed`.
- `Resources`: a `TypeId -> Box<dyn Any>` map (`insert`, `get`, `get_mut`, `remove`, `contains`, `get_or_insert_with`).
- `Events<T>`: double-buffered. `send` writes to a pending buffer; `update()` (called by the engine at the start of each frame) makes it the readable buffer and drops the old one, so an event sent in frame N is readable during all of frame N+1, exactly once. `extend_readable` puts events straight into the readable buffer (used for same-frame `Message`s). `EventRegistry` stores every `Events<T>` type-erased; `Ctx` keeps it in a private field and exposes `events::<T>()` (an empty queue if none exists; `Events::empty()` returns a `'static` one) `send::<T>(ev)` (readable next frame) and `send_now::<T>(ev)` / `send_batch_now(iter)` (readable right away by systems that run later in the same frame, via `extend_readable`; dropped at the next frame's update like other readable events; test in `tests/events.rs`, mod `send_now`).
- `Ctx`: `world` (`&mut hecs::World`), `types` (`&TypeRegistry`), `resources`, `time`, `input`, `gamepads` (`&GamepadState`), `window`, `commands` (public fields) plus `events()` / `send()` / `spawn(bundle) -> Entity`.
- `Commands` (`EngineCommands` is an alias): control requests `quit`, `set_title`, `set_frame_rate`, `set_cursor_visible`, `set_cursor_grab`, `set_fullscreen(bool)` (SDL `set_fullscreen`, the browser Fullscreen API on the web (needs a user gesture), ignored by the headless window), `set_cursor_icon(CursorIcon)`, `set_text_input`, `set_text_input_area(x, y, w, h, cursor)` (logical px; `WindowManager::set_text_input_area`; SDL `SDL_SetTextInputArea`, no-op on the web; `GameWindowManager::text_input_area()` returns the last value); world ops `spawn(&World, bundle) -> Entity` (reserves the entity at once with `World::reserve_entity`, queues the insert), `spawn_empty(&World)`, `despawn(e)`, `insert(e, c)`, `insert_bundle(e, b)`, `remove::<T>(e)`, `insert_raw(e, id, bytes)`, `remove_raw(e, id)` (raw ones resolved through the `TypeRegistry` at apply time). `append(&mut other)` moves another buffer's contents to the end (the later script system's path), `apply(&mut World, &TypeRegistry)` runs and clears the world ops in order. Ops on a dead entity are ignored (`log::debug!`); unknown ids or wrong sizes in raw ops are `log::warn!`ed and skipped. A reserved entity whose commands are dropped comes to life empty at the world's next flush (hecs behaviour, tested).

### Input (`src/engine/input.rs`, `input/`)
All platform-neutral; backends translate platform events into `InputEvent { timestamp_ns, window: WindowId, kind: InputEventKind, captured: bool }` with kinds `Key { physical: KeyCode, logical: Key, state, repeat, mods: Modifiers }`, `Text(String)`, `MouseMotion { pos, delta }`, `MouseButton { button, state, pos }`, `MouseWheel { delta, unit: WheelUnit }`, `Touch { id, phase: TouchPhase, pos }` and `TextEditing { text, cursor, len }` (IME preedit; SDL `TEXT_EDITING`; web `compositionupdate` / `compositionend` (empty text); never part of `InputState::text()`, only in `events()`) and `Window(WindowEvent)` (`Resized`, `ScaleFactorChanged`, `Focused`, `CloseRequested`). Conventions (same on both platforms): positions and deltas in physical pixels, origin top-left, y down; wheel `+y` is away from the user; `repeat` is false for releases; timestamps are monotonic nanoseconds, comparable only within one run. `KeyCode` is the physical key (layout-independent, `Unknown` if unidentified), `Key` is the logical key (`Named(NamedKey)`, `Character(lowercased string)`, `Unidentified`); typed text comes from `Text` events only. `Modifiers` is a hand-written bit set (`shift()`, `ctrl()`, `alt()`, `meta()`, `contains`, ...); the web cannot tell left from right.

`InputState` (at `engine.state.input`, also `cx.input`) is cleared by `begin_frame()` and filled by `apply()`: `pressed` / `just_pressed` / `just_released` / `any_pressed` / `pressed_keys`, `mouse_pressed` / `mouse_just_pressed` / `mouse_just_released`, `mouse_pos` (`None` until the first mouse event), `mouse_delta` and `wheel` (summed over the frame; wheel in lines, pixels / 40, pages x 20), `touches`, `text`, `modifiers`, `focused` and the raw `events()` of the frame. `Engine::add_input_filter(impl InputFilter)`: every filter is asked about every raw event (also injected / headless ones) in add order, before `handle_window_event` and `InputState::apply`; any `Filter::Captured` sets `InputEvent::captured`. Captured events still reach `InputState` (raw queries unchanged); `game_input()` ignores them. Rule: a key / button belongs to the game or to the UI by the press that made it held (repeats never change that); the release follows the owner, so a captured press never becomes a game press and a game press always gets its release (also when the release or focus loss comes in captured). Captured wheel, mouse delta and `Text` are left out of the game view; `mouse_pos` is not. A repeat never counts as `just_pressed`; losing focus releases every held key and button; `KeyCode::Unknown` is never tracked. It has unit tests and needs no window.

### Startup config (`src/engine/config.rs`)
`StartupConfig` is a one-shot, optional configuration set before `Engine::new` runs. Fields (JS uses camelCase): `wasmJsPath` (wasm-bindgen glue path used to spawn pool workers), `threads` (pool size; absent = automatic), `canvasId` (canvas element id; absent = `"canvas"`), `uiLayerId` (element the `efeengine-ui` web backend builds widgets in; absent = `"ui"`; core only stores it), `externalApi` (reserved, only stored) `gpuMode` (`GpuMode`: `"auto"` | `"wgpu"` | `"wgpu-gl"` | `"sdl"`, native; env `EFE_GPU_MODE` when `auto`) and `graphicsBackend` (`GraphicsBackend`: `"auto"` | `"webgpu"` | `"webgl"`, default `auto`, web only). On the web the JS page calls `__engine_start({ ... })` (generated by `#[main]`, see `templates/web/main.js`), which deserialises the object with `serde-wasm-bindgen`, calls `set_startup_config`, then runs the game's `main`. `set_startup_config` only accepts the first call (later calls warn and return `Err`), and `startup_config()` falls back to the default and locks it in, so the config has to be set before `Engine::new` (or any other reader) runs. Setting `wasmJsPath` also fills `WASM_PATH`, which the web thread pool reads. The old exported `set_wasmjs_path` (wasm) is `#[deprecated]` and only sets `WASM_PATH`. On native there is no JS, so the config is always the default unless Rust code calls `set_startup_config` itself.

`EngineConfig` (same file) is what `Engine::with_config` takes: `title` ("efeengine"), `size` (800x600, logical, native only), `vsync` (stored, the renderer will use it in Phase 4), `fixed_dt` (1/60), `max_fps` (`Some(60.0)`; `None` = uncapped), `threads`, `canvas_id` and `headless`. `EngineConfig::new(title)` and `EngineConfig::headless()` are shortcuts; `threads` / `canvas_id` left `None` are filled from the startup config.

### Messages and the flume queues (`src/engine/messages.rs`)
`MESSAGE_SYSTEM` is a `Lazy` unbounded `flume` channel (sender, receiver) in a static: the global queue for JS, workers and scripts. `send_message(msg)`, `message_sender()` (cloneable sender) and `recv_messages()` (a `Drain` over what is queued now) are the access functions. Each `Engine` also owns a private queue (`engine.sender()`); a non-headless engine drains both once per frame, a headless engine only its own (so tests do not see each other's messages). Input no longer travels as messages: window and input events go straight from the backend into the frame (see Input). Producers: JS (wasm export `send_message`, which deserialises a `JsValue` with `serde-wasm-bindgen`), the logger, any thread. Consumer: `Engine::drain_messages()` once per frame, which also exposes the messages as `Events<Message>`. `Message` derives `Serialize/Deserialize`; handling today:
- `Say(s)` logs info, `Log(LogMsg)` logs, `ChangeTitle(s)` sets the window title.
- `Stop` pauses a running engine (`Lifecycle::Paused`): frames still poll window events and handle messages, but run no stage, render nothing and do not advance game time (`Time::track` only remembers the clock, so resuming has no big delta). `Start` resumes it. `Kill` requests shutdown (`ShuttingDown`).
- `SetThreads(n)` resizes the global thread pool at runtime (`set_global_pool_size`, clamped to >= 1) and logs the new size.
- `SetFrameRate(f)` sets the native frame cap (`f <= 0` or non-finite = uncapped); the web loop is paced by `requestAnimationFrame`.
- `SetCanvasId(s)` (wasm only) forwards to the web window; it changes which canvas events and size sync use, but a surface that was already created is not recreated.
- `Null` is a no-op.

### Window backends (`src/engine/window/`)
`InnerWindow` (`HasWindowHandle + HasDisplayHandle`) is the backend trait: `set_title`, `size` (physical pixels), `scale_factor` (default 1.0), `logical_size` (default `size / scale_factor`), `poll_events(&mut Vec<InputEvent>)` (appends; the first call also emits the initial `Resized` and `ScaleFactorChanged`), and no-op-by-default `set_text_input`, `set_cursor_visible`, `set_cursor_grab`, `set_fullscreen` (+ `set_canvas_id`, `canvas`, `canvas_id` on wasm). It is deliberately not `Send`/`Sync`: SDL windows and the event pump must stay on the main thread, so `GameWindowManager` (which boxes one backend, holds the `surface_manager` and the `inject` queue, delegates raw-window-handle traits and implements `WindowManager`) and `Engine` are not `Send` either. `GameWindowManager::new(&EngineConfig)` picks the backend; `inject(ev)` queues an event that `poll_events` emits before the backend's own ones; `is_headless()`. Field order in `GameWindowManager` matters: the surface is dropped before the window it was created from.
- `HeadlessWindow` (`headless.rs`, all targets): fixed size, handles return `HandleError::Unavailable`, no events except the initial pair and injected ones. Used when `EngineConfig.headless` is set.
- Native `SdlWindowManager`: sets SDL hints (also `SDL_TOUCH_MOUSE_EVENTS=0`, so touch is not duplicated as mouse) and log priority to verbose, creates a centred resizable window of the configured logical size, and starts SDL text input. Each poll drains the SDL event pump into `InputEvent`s (timestamps from SDL, in ns): `Quit` / window `CloseRequested` -> one `CloseRequested` per poll; `FocusGained/FocusLost` -> `Focused`; `PixelSizeChanged` -> `Resized` (pixel size, so it matches the surface on HiDPI); scale changes (window `DisplayChanged` and the SDL `Display { ContentScaleChanged }` event) -> `ScaleFactorChanged` when the scale differs; `KeyDown`/`KeyUp` -> `Key` (physical from the scancode, logical from the keycode or `SDL_GetKeyFromScancode` for layouts outside the sdl3 `Keycode` enum, `repeat` on KeyDown); `TextInput` -> `Text`; mouse motion/buttons/wheel (positions scaled from logical window units to physical pixels; wheel in `Line` units, flipped-direction undone; events from the touch pseudo-mouse skipped); `FingerDown/Motion/Up` -> `Touch` (normalised position x pixel size). `TouchPhase::Cancelled` is never produced natively (sdl3 0.14.42 has no finger-cancel event). `set_text_input`, `set_cursor_visible` and `set_cursor_grab` (relative mouse mode) are implemented; `sdl_impls.rs` holds the pure conversions (`physical_key`, `logical_key`, `modifiers`, `mouse_button`).
- Web `WebWindow` (`web_backend.rs`, with key conversion in `web_impls.rs`): works with a `<canvas>` looked up by id (startup config `canvasId`, default `"canvas"`, changeable with `SetCanvasId`). It registers DOM listeners that push `InputEvent`s into a local queue which `poll_events` takes: `keydown`/`keyup` on `window` (ignoring IME composition; `preventDefault` only for game keys such as arrows, Space, Tab, paging keys and Backspace, and never with Ctrl/Alt/Meta or in input/textarea/select/contenteditable), `compositionend` on `window`, `focus`/`blur` on `window` and `visibilitychange` on `document` (a hidden tab counts as unfocused; duplicates are dropped). Pointer events (`pointerdown/move/up/cancel`, with `setPointerCapture`) on the canvas: `pointerType == "touch"` gives `Touch` events (cancel maps to `TouchPhase::Cancelled`), mouse and pen give `MouseMotion` / `MouseButton`; `wheel` is non-passive with `preventDefault` and reports `Pixel` / `Line` / `Page` units with the sign flipped to the engine convention; `contextmenu` is suppressed on the canvas; `templates/web/index.html` sets `touch-action: none`. Text: on `keydown` a key that is a single grapheme (no Ctrl/Meta unless AltGraph) emits `Text(key)`, plus `compositionend` -> `Text(data)`; there is no `beforeinput` or hidden-input IME path. Text events are on by default and `set_text_input(false)` turns them off. When focus is lost, a `Released` is synthesised for every held key first (keyed by physical key, `Unknown` skipped), because the browser does not deliver them. The canvas gets `tabindex="0"` if missing and is focused on `pointerdown`. Every `poll_events` call (and once at construction) syncs the canvas drawing-buffer size to CSS size x `devicePixelRatio` and reports changes as `Resized` (the canvas size is polled, there is no `ResizeObserver`), and changes of `devicePixelRatio` as `ScaleFactorChanged` (a `matchMedia("(resolution: ...dppx)")` listener also reports them and is re-armed from the per-frame poll). A 0x0 layout is ignored. `size()` returns the canvas buffer size. `set_title` also sets `document.title`; the cursor is hidden via the canvas CSS `cursor`; `set_cursor_grab` uses `requestPointerLock` / `exitPointerLock` (while locked, motion deltas come from `movementX/Y`). The raw-window-handle impls are dummy values (wgpu is given the canvas element directly). Listeners are removed on drop.
- Gamepads (`input/gamepad.rs`): polled once per frame into `GamepadState`, not part of the `InputEvent` stream. Native uses the SDL gamepad subsystem (pads opened at startup, `ControllerDeviceAdded/Removed` for hotplug). Web polls `navigator.getGamepads()` each frame and reads only pads with the `"standard"` mapping (others are ignored and logged once). Compile-checked only (no pad was available).
- Web input robustness (`web_backend.rs`): mouse buttons are diffed from the `PointerEvent.buttons` mask (chorded buttons are tracked); on blur, buttons and touches are released or cancelled along with keys; a Meta keyup releases the other held keys (macOS sends no keyup for them); key and text events are ignored while focus is in an editable page element; canvas listeners are attached when a canvas appears later; pointer lock is re-requested on `pointerdown` when a grab is wanted.
- Native-window and browser behaviour is compile-checked only (no automated run); `examples/input_test` is the manual check.

### Rendering (`src/engine/render/`, `src/engine/transform.rs`)

- `gpu.rs`: `GpuContext::new(&GameWindowManager)` creates the wgpu `Instance` (web: WebGPU or WebGL2 per the startup config), the surface (before the adapter: WebGL can only give an adapter for a canvas), the adapter and device (limits from the backend, `using_resolution(adapter.limits())`), picks an sRGB surface format and the first present mode, and configures the surface. `gpu()` gives the `Gpu` view, `resize`/`reconfigure` configure again.
- `extra_surface.rs`: `ExtraSurface` / `SurfaceFrame` (`for_canvas` wasm32 only; `format`, `resize`, `acquire`, `present`; `from_surface` is the crate-internal hook for a native `for_window`). Backings: Direct (a `wgpu::Surface` on the shared instance/device, WebGPU; storage format = main surface's if supported else first non-sRGB, configured with `view_formats` = its sRGB variant and frames handed out through an sRGB view, `format()` is the sRGB variant; alpha PreMultiplied > Inherit > first) and Copy (WebGL2: the device lives in the main canvas's GL context, other canvases cannot share it). Copy path: the canvas gets a 2D context; `acquire` hands out an internal `Rgba8UnormSrgb` texture; `present` submits `copy_texture_to_buffer` (rows padded to 256 B) and `map_async`; the next `acquire`/`present` polls the device (`PollType::Poll`), and a completed map is un-premultiplied on the CPU (decode sRGB, divide by alpha, encode; the colour is premultiplied in linear space) into a JS-owned `Uint8ClampedArray` (wasm memory may be a SharedArrayBuffer, which `ImageData` rejects) and `putImageData`d. One frame of latency; one readback in flight per surface, a frame presented meanwhile is re-read at the next `acquire`. Cost per frame: GPU->CPU readback + a CPU pass over w*h*4 bytes. The chosen path is logged once. Not browser-tested yet.
- `mod.rs`: `Gpu<'a> { adapter, instance, backend, device, queue, surface_format, size, scale_factor }`, `trait Renderer2D` / `Renderer3D` (`init`, `resize`, `render(gpu, &Target, &Frame2D|&Frame3D, &TextureChanges)`), `Target { view, clear }`, `trait CustomRenderer` (old `Renderer`: `render(gpu, view, &RenderFrame)`), `ClearRenderer` (a `Renderer2D` that only clears). `renderers.rs`: slots and pass order; `Engine::set_renderer_2d` / `set_renderer_3d` / `set_renderer`.
- `frame.rs` / `extract.rs`: `render_extract` builds the `RenderFrame` resource: the first active `Camera` by entity id per kind (orthographic into `d2.camera`, perspective into `d3.camera`; `CameraView`, matrices column-major `[[f32;4];4]`, with `target`), visible `Sprite`s as `SpriteInstance`s in `d2.sprites` sorted by `(layer, entity id)`, `MeshHandle`s as `MeshInstance`s in `d3.meshes`, drained texture changes. `RenderWarnings` latches the "warn once" flags.
- `textures.rs`: `Image` (checked RGBA8, private fields), `Textures` resource (`add`, `add_png`, native `load_png`, `replace`, `remove`, `get`, `size`, `drain_changes`), `TextureChanges`.
- `png.rs`: pure-Rust PNG decoder (`miniz_oxide` inflate + `crc32fast`), `Image::from_png`, `PngError`. 8-bit gray / gray+alpha / RGB / RGBA / palette(+`tRNS`), 1/2/4-bit gray and palette, all filters, many `IDAT`; refuses interlaced, 16-bit, bad CRC, truncation, over 16384 per side. Unit tests include a byte-mutation no-panic loop.
- `sprite_renderer.rs` + `sprite.wgsl`: `SpriteRenderer`, the default `Renderer2D` (`set_renderer_2d(SpriteRenderer::new())` to pick another filter): mirrors the frame's `TextureChanges` into GPU textures (id 0 = white), camera uniform, one 112-byte instance per sprite in a growing vertex buffer, one instanced draw per run of same-texture sprites, straight-alpha blend, nearest sampler (`with_linear_filtering` for bilinear); textures live in a shared `GpuTextures`, and `frame.d2.draw` (a `DrawList` in screen pixels, e.g. the debug draw) is drawn over the sprites in the same pass by a `WgpuDraw2D`. WebGL2-safe (no storage buffers, no `first_instance`, no `base_vertex`).
- `transform.rs`: `velocity_system`, `propagate_transforms` (computes `GlobalTransform`, rebuilds `Children`, handles stale parents and cycles).
- Components (`components.rs`): `Camera`, `TextureHandle`, `Sprite`, `Visibility`, `Parent` (script-visible), `Children` (Rust-only), `GlobalTransform` (script-visible, read-only by convention).
- Tests: `tests/render.rs`. Docs: `docs/RENDERING.md`. Template: `examples/custom_renderer`; built-in renderer demo: `examples/coin_dash`.

### Logger (`src/engine/log.rs`)
`Logger` trait (`logger_name`, `info`, `warn`, `error`, `alert`, `log(&LogMsg)`). `LogMsg` is `Info/Warn/Alert/Error(String)` with `get_msg()` (prefixed) and `get_inner()`. The free functions `global_info/warn/alert/error` send commands over a flume channel to a process-wide logger that runs in a dedicated pool worker (`new_worker_global()`), created lazily on first use; `set_global_logger` swaps the logger at runtime; dropping the sender sends `Shutdown`. `debug_info/warn/alert/error` do the same only when this crate's `debug_log` feature is on. Default loggers: native `sdl3::Log` (every level goes to `SDL_Log`, no level distinction), wasm `web::Log` (console functions). `LogCrateLogger` forwards to the `log` crate; headless engines use it as their engine-internal logger. `Engine` also holds its own separate `Box<dyn Logger>` used for engine-internal messages.

### World, components and the type registry (`components.rs`, `types.rs`, `commands.rs`)
The world is a plain `hecs::World` (`state.world`, `cx.world`); Rust systems use typed hecs queries and change structure through `Commands`. Components (`components.rs`): `Transform { position: Vec2, rotation: f32, scale: Vec2 }` (default scale 1, `from_position`), `Velocity { linear: Vec2, angular: f32 }`, `MeshHandle { id: u32 }`, all `#[repr(C)]`, `Pod` and `#[derive(ScriptType)]`; `Name(String)` is Rust-only.

`TypeRegistry` (`types.rs`): `register::<T: ScriptType + Component>()` / `register_owned::<T>(owner)` (owner default `engine`) and `register_struct(StructDesc)` (layout-only, `component` must be `None`, empty owner becomes `engine`) return the id `fnv1a32(name)`; a duplicate name, a Rust type registered twice, an id collision or a layout failing `StructDesc::validate` is a `TypeError`. Lookups: `get(id)`, `by_name`, `of::<T>()`, `component(id)` (`CompError::UnknownId` / `NotComponent`), `entries()`. A `TypeEntry` has `id`, `name`, `desc` (`StructDesc` with `component: Some(id)` for components), `size`, `align`, `is_component`, and byte functions `read(&World, e, &mut [u8])`, `write` (in place, component must exist), `insert`, `remove`, `has`; lengths are checked before `bytemuck::pod_read_unaligned`, so a wrong size is `CompError::WrongSize`, never a panic; a dead or stale entity is `CompError::NoEntity`, a missing component `CompError::Missing`. `ScriptField` (PRIM, COUNT) is implemented for the integer and float primitives, `[T; N]` (COUNT multiplies) and glam `Vec2/3/4`, `IVec2/3/4`, `UVec2/3/4`. Entities cross boundaries as `u64`: `entity_to_bits(e)`, `entity_from_bits(bits) -> Option<Entity>` (`None` for 0 and impossible patterns; a stale but well-formed handle then fails in world operations). The old `GameObject` / `EngineWorld` / `add_object` are gone. The old `GameSystem` trait, `add_system()` stub and `GameRunner` are gone; systems are plain closures registered with `Engine::add_system(Stage, ..)`.

### Scripting (`src/engine/scripting/`)
One VM per world. `Scripting` (`EngineState.scripting`, `Engine::scripting()` / `scripting_mut()`, `Ctx.scripting`) owns the one `efevm::HostRegistry<ScriptHost>` and every loaded module (one `efevm::Instance` each; no instance per entity). The registry is the only table: instances link against `registry().imports()`, and `Engine::api_index()` is `registry().index()`. Files: `host.rs` (`ScriptHost`: world moved in with `mem::take` while scripts run, a `Commands` buffer appended to the stage's, copies of `Time` and `InputState`, `ScriptEvent`s, log lines, the module table; a running module's instance is taken out of its slot, so re-entering it is a clean trap), `api_engine.rs` (the `engine.world/input/time/events/log` host functions, owner `engine`, version 1 (`engine.events` is version 2, see Typed script events), and the `engine.mods` namespace, version 2, which has no functions yet (`engine.mods.export` is gone: a mod declares what it provides in its section 13 interface; asset access comes with packages); status codes 0 ok, 1 stale entity, 2 component missing, 3 unknown component id, 4 wrong size, 5 read-only component (`set`/`insert`/`remove` on a `readonly` one), -1 other; `engine.world.changed(entity, component, since)` and `tick()` are the change-detection pair, `changed` returns negated codes -1/-2/-3), `mods.rs` (`load_module`, `load_mod(bytes, ModOptions { name, version, budget, allowed, doc })`; for a mod with an interface it defines the namespace `<name>` (owner `<name>`), registers own structs, checks copied structs against the registry (`ScriptError::StructMismatch`) and registers one trampoline per provide, after a dry run on a scratch registry, so a failed load registers nothing and uses no module id; a game module with an interface is `ScriptError::NotAMod`; `unload` is refused with `ScriptError::Needed` while another module imports from the namespaces the mod owns or copies its structs, `unload_cascade` removes dependents first; native `watch` and hot reload, which is refused (`ScriptError::ReloadRefused`, old version keeps running) when a loaded dependent would break), `provides.rs` (the trampoline looks the provide up in the slot's current module on every call, copies `str`/`bytes`/`&Struct` arguments into the provider's scratch region left to right at 8-aligned addresses, charges `1 + (in + out) / 256` units from the provider's remaining budget, runs the function by index, copies `bytes`/struct ranges back only after a normal return), `system.rs` (`Script { module, entry, state }` and the script system, first in `Update`: `init()` once, `frame(dt)` per frame, `entry(entity, dt, state) -> state` per `Script`; per-module per-frame budget, default 1 000 000 units; out of budget logs a warning and skips the rest of that module this frame; a trap logs an error with function names and the next frame runs again).

### Mod components (`scripting/components.rs`, `types.rs`)
A mod declares `[[meta.component]]` (name, fields of efevm `Prim`s with optional `count`, `tracked`); `parse_components` lays them out like `repr(C)` and they are registered as `mod:<mod>/<Name>` (owner `mod:<mod>`; `efevm::api::is_type_name` lets `StructDesc::validate` accept the form) in the `TypeRegistry` (`Storage::Dynamic`), the API index and the world (`register_dynamic`) before `init`. `TypeEntry` read/write/insert/remove/has/`component_id` go through the world's dynamic API; `Ctx::dyn_get`/`dyn_get_mut`, `ParCtx::dyn_get`, `TypeRegistry::view`/`view_mut` (`DynView`, `DynComponent`) are the Rust access. `Grant::max_component_types`/`max_component_size` limit them; `ModRequest::components` shows them to the policy. Script-spawned entities get the Rust-only `SpawnedBy(ModuleId)`; every unload despawns them and unregisters the mod's components (`release_module_state`). A swap (`reload_mod`/`reload_mods`) keeps the old registrations in a stash, adopts identical layouts, queues migrations for changed ones and runs them in `finish_swap` after success (rollback never touched the data). In-place hot reload refuses changed declarations. Tests: `tests/mod_components.rs`.

### Mod packages (`src/engine/scripting/packages.rs`, E8)
`Engine::load_input(LoadInput::Package { label, bytes })` and `Engine::load(path)` for a `.efmod` file; sources registered with `add_mod_source` are loaded by `load_mods()` (E10). Removed in E10, with no replacement under the same name: `load_package`, `load_packages`, `load_mods_dir` (the directory scan is `DirSource`), `load_module_file`. Native `watch_package(id, path)` / `package(id) -> Option<&PackageInfo>` / `package_asset(id, path)` / `set_mod_policy(policy)`. One package is one unit: one module, one `Grant` (the allow-list of that module; no per-file permission). Load sequence: `ScriptCache::read_package(bytes)` (memory-cached `efemod::Package::read` with `ReadLimits::default()`), `game` check (`ModError::GameMismatch`, the game is the registry's `game()`: config title or `set_game_name`), id clash (`ModError::IdClash`: the id equals or prefixes a registered namespace, or is `engine`/`std`/`efe`; checked before the policy; an id already used by a loaded module is `Script(NameTaken)`), dependencies (each must be a loaded package within its range, else `Resolve(Missing | Version)`; a bare `load_mod` module never satisfies one), policy (`ModPolicy::grant(&ModRequest { manifest, imports })`, `Err` is `Denied`; `Grant::namespaces` is intersected with `manifest.permissions.namespaces`; budget and memory pages as granted), imports must lie within grant plus dependency ids (`NotGranted` names them), `load_mod` with `ModOptions { name: id, version: api_version, budget, memory_pages, doc: namespace_doc, allowed }` (`memory_pages` becomes the instance's `Limits::max_memory_pages`), `init` runs at once, and the `PackageInfo { manifest, grant, assets }` is stored in the module slot (dropped at unload). `DefaultPolicy` grants no namespace: a package importing engine or game namespaces is `NotGranted` until the game installs a policy; a package that only imports its dependencies' namespaces loads. `load_mods` lists every source, reads the manifests only, resolves the whole set with `efemod::resolve` against the loaded packages (duplicates, missing, versions, cycles), loads in dependency order and skips dependents of a failure (`Resolve(DependencyFailed)`). `engine.mods` (version 2) has `asset_len(path)` and `asset_read(path, buf)` reading the running mod's own package assets (path without `assets/`; -1 when there is none). `watch_package` re-reads the package when its mtime changes: the id must be unchanged, dependencies must still resolve, loaded dependents must accept the new version, the policy is asked again, then the `reload_module` rules apply; any failure is logged and the old version keeps running. Tests: `tests/packages.rs`, plus a package case in `tests/api_index.rs`.

### Loading and caches (`load.rs`, `cache.rs`, E10)
`Engine::load(path)` (native) dispatches by path: a directory with `mod.toml` is a folder mod (label = folder name), `*.efa` is game code compiled through the cache against the full registry index, `*.efvm` is game code, `*.efmod` is a package, anything else is `LoadError::UnknownKind`. `load_input(LoadInput)` takes the same kinds as bytes or sources: `Efa { name, files, root }`, `Efvm { name, bytes }`, `Package { label, bytes }`, `Folder { label, files, assets }` (`Efa` and `Folder` need feature `efa`). Errors: `LoadError::{Io, Compile, Script, Mod, CompilerDisabled, UnknownKind}`; folder build problems (`mod.toml`, limits, compile diagnostics as text) are `ModError::Build`.
- **Trust.** `Efa` and `Efvm` run with no policy, as `load_module` does. `Package` and `Folder` pass the game check, the id-clash check, dependencies, the `ModPolicy` and the asset check. Each asset goes to the first `AssetHandler` whose `matches` is true; `check` runs before instantiation and a refusal is `ModError::Asset` (nothing loads). `commit` runs after a successful instantiation; `unload` runs on unload for the handlers that committed.
- **Folder mods.** `prepare_mod` (`BuildLimits::default()`), `ScriptCache::compile` of the entry against the game index (the registry index without the namespaces of loaded packages and mods) merged with each declared dependency's index, then `finish_mod`.
- **Sources.** `ModSource::list()` returns `ModItem { label, body }` with `ModBody::Package(bytes)` or `ModBody::Folder { files, assets }`; `changed()` names labels changed since the last call. `DirSource::new(dir)` (native) lists the `*.efmod` files and the folders with a `mod.toml` directly inside `dir`, sorted, not recursive. Nothing installs a source automatically. Hot reload: the script system calls `changed()` at most every 0.25 s; a changed loaded label is reloaded in place and its folder dependents are rebuilt when their bytes change; a failure is logged and the old version keeps running. `.efa` game scripts are not watched.
- **Cache.** `Engine::cache()` returns the `ScriptCache`, configured by `EngineConfig::script_cache: CacheConfig { disk: CacheDir, memory, max_disk_bytes }` (defaults: `CacheDir::Platform`, memory on, 64 MiB). Memory: blake3 key with a full-byte comparison on a hit, 64 MiB cap (cleared when full), used by `decode` and `read_package`. Disk (`efa` feature; none on web): `<base>/efa/v1/<xx>/<hash>.{efvm,deps}` for `.efa` and folder compiles; the key covers the format version, `efa::VERSION`, the root file's name and contents, and the index hash. A hit re-hashes every file in `.deps` through the same `FileSource`, decodes with verification, and compares the module's index hash; any mismatch deletes the pair and compiles again. Writes go to a temp file, then `rename`; write errors are logged and ignored. `max_disk_bytes` is enforced once per engine, when the directory is first used. `CacheDir::Platform` is `$XDG_CACHE_HOME` or `$HOME/.cache` (Linux), `$HOME/Library/Caches` (macOS), `%LOCALAPPDATA%` (Windows), then `efeengine/<game>` with the game name sanitised; `CacheDir::Off` and `CacheDir::Path(p)` are for tools and tests.
- **Tests.** `tests/load.rs` uses `CacheDir::Path` in a temp directory or `CacheDir::Off`, never the platform directory.

### Typed script events (E8.13)
Events are registered like functions, which puts them in the index: `Engine::register_event(EventDesc)` / `Scripting::register_event` (namespace defined with `define_namespace`, owner from it, payload a registered struct, doc not blank; `engine.*` namespaces are refused for games; the engine registers no events of its own today, it sends none from Rust), and a mod's `Interface.events` (section 13) are registered at load with owner = mod id, in the same dry run (scratch registry) and rollback path as provides, before the mod's own section 14 is linked. A mod may therefore list its own events in section 14: its link check runs on a copy without its own-namespace events and own entries of section 12, which are checked against the interface instead (`UnknownEvent` / `EventPayload` / `NamespaceVersion`), then the real module is linked after registration (a failure there unregisters the mod's entries again). A game module cannot provide events (`NotAMod`).

ABI (`engine.events`, version 2; the string-named raw-bytes `send/count/read` of version 1 are gone): `send(ev: i32, payload: ptr)`, `count(ev: i32) -> (count: i32)`, `read(ev: i32, index: i32, out: ptr) -> (status: i32)` (0, or -1 when there is no such event). `ev` indexes the section 14 (`ModuleData.events`) of the module whose code is running (`ScriptHost.current`, so inside a provide it is the provider); an id outside it is `Trap::Host("engine.events.<fn>: module `m` has no event with id N ...")`. The payload size comes from that `EventRef` (equal to the registered size, guaranteed by the link check); bounds are checked before anything is allocated or copied, an out-of-range `payload`/`out` is `OutOfBounds`, no-payload events ignore the pointer. Cap: 4096 queued events per frame from scripts (`MAX_EVENTS`); further sends are dropped and counted (`ScriptHost.dropped_events`), `Scripting::dropped_events_last_frame()` returns the count of the last script run and `leave()` logs one warning per run with drops: `N script events dropped this frame (cap 4096)`. Rust sends do not count against the cap.

Rust boundary: `ScriptEvent { event: String /* "namespace.name" */, payload: Vec<u8> }` is what travels in `Events<ScriptEvent>` (readable next frame). Sending it from Rust names a registered event and the payload must be exactly the payload struct's size, else the send is refused with `Err(ScriptEventError::{Unknown, Payload})` and nothing is queued (decision: refuse, not log-and-drop, because the caller can act on it): `Ctx::send_script_event(event, &[u8])`, `Engine::send_script_event`, `ScriptHost::send_event(event, &[u8])` (for game host functions; counts against the cap). Reading: `Ctx::script_events(event) -> iterator of &[u8]`, `ScriptHost::events_named`; entries whose length differs from the registered size (e.g. after a reload) are skipped. `Events<T>` for Rust-only events is unchanged.

Permissions and dependents: every namespace of `ModuleData::event_namespaces()` must be allowed like an import (prefix rule; own namespace always allowed): `ScriptError::Disallowed` / `ModError::NotGranted` name it (the messages say "imports or events"); for packages the allow-list is grant plus dependency ids. `ModRequest` has a separate field `events: &[String]` (event namespaces without the package's own id) next to `imports`, so a policy can tell calling from event use (decision: separate, not merged). A module depends on mod Y also when its section 14 refers to an event of a namespace Y owns: unload is `Needed`, the cascade removes it first. Hot reload (`reload_module`) is refused with `ReloadRefused` when a loaded dependent uses an event the new version drops or whose payload (struct name or size) changes; dropped events are unregistered (the registry removes by owner, so the mod's entries are rebuilt as for dropped provides), added ones registered, changed docs replaced. Tests: `tests/events.rs`, the event cases of `tests/api_index.rs` and `tests/scripting.rs`.

Single registration path: `Engine::register_component::<T>()` / `register_component_owned` / `register_struct` add the type to the `TypeRegistry` and its `StructDesc` to the registry (the index); `TypeRegistry::register*` are `pub(crate)`, so a component id that `engine.world.*` accepts is always in the index. Host functions: `Engine::define_namespace` (owner `engine` is reserved) and `Engine::register_host_fn(HostFn, closure over &mut Caller<ScriptHost>)`. Loading through `Engine::load_module` / `load_mod` / `load_input` runs `init` at once (so a mod's provides are in the index when it returns, registered before `init`); `Engine::unload_module` removes the instance, the owner's index entries and its component types (`Needed` while dependents are loaded; `Engine::unload_module_and_dependents(id) -> Vec<ModuleId>` unloads them first, latest loaded first). Index: `api_index()`, `export_api_index()` (JSON), `set_game_name`, `write_api_index(path)`; with `EFE_API_EXPORT=<path>` set when the engine is created it is headless and `game_loop()` writes the index there and returns without running frames (`set_api_export_path` does the same programmatically). A plugin can register its own host functions the same way (the UI plugin registers namespace `ui` with owner `efeengine-ui`; its closures capture shared state because lanes run on a snapshot); `ScriptHost::is_mod(id)` says whether a module is limited to a grant, `current_module()` / `module_name(id)` identify the caller (public, for such plugins). Key names for `engine.input` come from `KeyCode::from_name` (case-insensitive variant names). Tests: `tests/scripting.rs`, `tests/provides.rs` (provides, copy ABI, dependents, hot-reload rules), `tests/packages.rs` (packages), `tests/api_index.rs`, a re-entrance unit test and a version-change unit test in `scripting/mod.rs`.

xtask interplay (`xtask/src/api.rs`, `cargo xtask --help`): `cargo xtask api-export <example> [-o FILE]` builds the example natively and runs it with `EFE_API_EXPORT=<file>` (default `target/efapi/<example>.efapi`); the engine then runs headless, `game_loop()` writes the index and returns. Native `cargo xtask build|run <example>` also writes `<example>.efapi` beside the binary and assembles `examples/<example>/scripts/*.efa` against it with the efescript CLI into `scripts/*.efvm` (a script with a `; needs-mod: NAME` header is checked by `cargo xtask check-scripts` against the game index merged with that mod's `.efapi` fragment, see `docs/MOD_LOADING.md`). `dist` copies the `.efapi` into `dist/<example>/`. The `.efapi` file is the contract between the game, the efescript assembler (`--api`) and the editor's LSP (`efescript lsp --api`). `efeengine-core` does not depend on the `efescript` crate.

### Thread pool (`src/engine/thread_pool.rs` + `thread_pool/`)
Common API: `Jobs::{Job(Box<dyn FnOnce()+Send>), Kill}`, `JobHandle<T>` (oneshot receiver: `join`, `is_finished`, `try_recv`, `recv_timeout`), `GLOBAL_POOL: Lazy<ThreadPool>`, `spawn_global(f)`, `spawn_job_global(job)`, `new_worker_global()` (a `WorkerHandle` with its own queue and thread, used by the logger).

Sizing: `CORES` is an `AtomicUsize` (written more than once, so not a `OnceCell`) holding the requested size (0 = nothing requested; the pool then defaults to 2 workers). `init_global_pool(n)` stores `n` (at least 1) and forces the pool. `init_global_pool_auto()` calls `detect_cores()` (native: `available_parallelism`; web: 1 if the page is not `crossOriginIsolated`, otherwise `hardware_concurrency`) and `worker_count(cores)`, which reserves 1/2/3/4 cores for main/render/audio threads depending on the core count (always at least 1 worker). On native the env var `EFE_THREADS` overrides the automatic count (only on the automatic path; an explicit `threads` in the startup config wins over it). The size can change at runtime: `set_global_pool_size(n)` (clamped to >= 1; only records the size if the pool does not exist yet), `global_pool_size()` (current target) and `Message::SetThreads(n)`. Resizing is meant to be called from the main thread. The module doc says wgpu, SDL and DOM objects must stay off the pool.

Shared design (native and web): all resizable workers pull from one shared flume channel. Growing spawns workers; shrinking queues `Jobs::Kill` messages and never blocks, so busy workers finish their current job and then exit. `KillGate` counts pending "please exit" requests: a worker that pops a `Kill` only exits if it can take one request from the gate, so stale kills (a later grow cancelled the shrink) are ignored. Dedicated workers have no gate: any `Kill` stops them.
- native (`native.rs`): N `std::thread`s share the channel; a panicking job is caught so it does not kill the worker; finished workers are joined on the next resize; dropping the pool sends kills and joins workers; dedicated workers get a `Kill` first (the pool keeps its own sender for each, and `WorkerHandle::drop` also sends one), so the join does not wait on a live handle.
- web (`web.rs`): each worker is a module `Worker` created from a Blob URL built from `worker.js` with `*project_path*` replaced by the wasm-bindgen JS glue URL (`WASM_PATH`, filled from the startup config's `wasmJsPath` or the deprecated `set_wasmjs_path`). The Worker is sent `{module, memory, id, ptr}`; the JS does `initSync({module, memory})` (shared memory) and calls the exported `worker_loop(ptr)`, which blocks on the flume receiver and runs jobs until it takes a `Kill`. Resizing is implemented and non-blocking: exited workers are only `terminate()`d (dropped) on the next resize call. If creating a worker fails, `Worker::new` logs and returns `None`, and the pool keeps the workers it created (no panic). Dedicated workers use ids from 31000. Without a wasm JS path (`wasmJsPath` not set) no worker script URL exists: the pool is created with zero workers and a warning is logged, so jobs sent to it never run (a `JobHandle::join` on them blocks); a dedicated worker is not created and its jobs are discarded. `worker_loop_once` + `worker_once.js` implement a one-job worker type (`WorkerType::Once`) that nothing selects yet.

### Frame flow
1. Platform callback: native loop iteration (frame-limited to `max_fps`) or `requestAnimationFrame`; `tick()` reads the clock and calls `frame(now)`.
2. `time.advance`, `events.update_all`, `input.begin_frame`.
3. `windows.poll_events(&mut buf)`: injected events, then SDL events / the DOM listener queue (plus the web canvas size sync). Each event is handled by the engine (state, surface, close) and applied to `InputState`.
4. `drain_messages()`: the engine's own queue (and the global queue unless headless) -> control handling + readable `Events<Message>`.
5. Stages: `Startup` (once), `PreUpdate`, `FixedUpdate` x n, `Update`, `PostUpdate`, `RenderExtract`; `EngineCommands` applied after each.
6. If graphics are initialised: the engine's `Renderer` draws the `RenderFrame` (see Rendering above); `Outdated`/`Lost` triggers a surface reconfigure.
7. On `Kill`: `Shutdown` once, then the loop ends.

### Components: `#[script_component]`, `#[derive(Component)]`, `Engine::register`

## Platform notes
- Workspace root `.cargo/config.toml` sets, for `wasm32-unknown-unknown`, rustflags: `+atomics`, `+bulk-memory`, `--shared-memory`, `--import-memory`, `--max-memory=2147483648` (2 GB), and exports of `__wasm_init_tls`, `__tls_size`, `__tls_align`, `__tls_base`, `__heap_base`, `__data_end` (needed by the wasm-bindgen threads transform). Atomics require a nightly toolchain with `-Z build-std` (std must be rebuilt with atomics); the page must be cross-origin isolated (COOP/COEP) for `SharedArrayBuffer`, otherwise the pool degrades to a single worker (and without `wasmJsPath` it has no workers at all).
- Native needs SDL3. By default it links a system SDL3 (on Windows through vcpkg: `build.rs` uses the `vcpkg` crate, `VCPKGRS_DYNAMIC=1`; `[package.metadata.vcpkg]` has a hard-coded Scoop vcpkg root `C:/Users/efe/scoop/apps/vcpkg/current`). The `static` feature builds SDL3 from source and links it statically.
- wgpu backends: native `PRIMARY` (Vulkan/Metal/DX12) then `GL` (one instance each; `GpuMode` from `StartupConfig::gpu_mode` / env `EFE_GPU_MODE`: `auto`, `wgpu`, `wgpu-gl`, `sdl` reserved for 4C.4); wasm picks WebGPU or WebGL2 per `graphicsBackend` (see Renderer; `auto` means WebGL2 on desktop Linux). The wasm surface is found by the canvas id from the startup config (default `"canvas"`). The unused `RendererState` still hard-codes `GL | BROWSER_WEBGPU` on wasm.
- Native `Kill` (or a close request) breaks the loop so `game_loop` returns; wasm just stops requesting frames.
- Several log strings and comments are in Turkish.

## Status and known gaps
- Wasm rendering depends on the page: it needs a `<canvas>` with the configured id, and WebGPU-vs-WebGL2 selection is a heuristic (user agent for the Linux case). If graphics init fails the engine keeps running without drawing. The web raw-window-handle impls are dummies.
- Native window and browser input paths (SDL events, DOM listeners, pointer lock, text/IME, DPR changes) are only compile-checked; the headless tests cover `InputState` and the frame loop, not the backends. Text input on the web has no hidden-input / virtual-keyboard path. Gamepads are compile-checked only (no pad was available). Native touch never reports `Cancelled`. `Engine::render()` is empty, and `vsync` is stored but unused (the native loop only sleeps to `max_fps`).
- `StartupConfig.external_api` is stored but unused; `graphicsBackend` is ignored on native; `SetCanvasId` after graphics init does not recreate the surface.
- The only built-in drawing code is `SpriteRenderer` (the default 2D renderer; `ClearRenderer` only clears; no text or meshes; `Draw2D` and `DebugDraw2D` exist since 4C.3). `shaders/video.wgsl` is unreferenced. The PNG decoder skips interlaced and 16-bit images and gray/RGB `tRNS` keys; no other image formats.
- `Flags` is an empty placeholder.
- Thread pool: errors from `send` are ignored throughout; a native dedicated worker busy with a long job delays dropping the pool; resizing is expected from a single (main) thread; `WorkerHandleOnce` and `worker_loop_once` are unused; the Windows vcpkg root is machine-specific.
- `JobHandle::join` on wasm blocks the calling thread (warns "experimental"); the wasm pool needs the wasm-bindgen glue path (`wasmJsPath` in the startup config, or the deprecated `set_wasmjs_path`) to have been set first; without it the pool has no workers, a warning is logged and queued jobs never run.
- Two logging paths exist: the engine's own `Logger` (`global_info` etc.) and the `log` crate backend above (for third-party crates); headless engines skip the backend and log through `LogCrateLogger`. Native `Logger` levels map to plain `SDL_Log` (no severity); the global logger permanently occupies one dedicated worker thread.
- Tests: real unit tests for `InputState`, `Time`, `Events`, `Resources`, `EngineConfig`, `HeadlessWindow`, the thread pool (grow/shrink, jobs across resizes, global size API) and the `Message` JSON shape; `tests/headless.rs` runs a headless engine end to end. A few leftover experiments (hecs prints, mpsc) have no assertions. `serde_json` is a dev-dependency used by the JSON-shape test.
- Leftover/debug code: wasm `zort()` export (`lib.rs`), `worker_once.js` `setTimeout` console.log.
