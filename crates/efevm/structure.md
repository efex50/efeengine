# efevm

`efevm` is the register-based bytecode VM for efescript, roadmap item E1 (the spec is `SPEC.md`, draft 1). It is a separate crate from the old efescript VM in `crates/efescript`, which keeps running until the assembler moves to `efevm` (E2). It has a verifier that runs at load time, a binary `.efvm` codec, a fiber-based interpreter with an instruction budget, and no I/O: everything outside the VM is a host function supplied by the embedder. **Used by: nothing yet.**

## Main concepts
- **Value types and functions** (`types.rs`): `ValType` is `I32, I64, F32, F64` (bytes 0-3 in the binary format). `FuncType { params, results }`. `Limits` (`types.rs:46`) holds the embedder caps: `max_memory_pages` (default 16384), `max_call_depth` (10 000), `max_registers` (1 << 20, per fiber), `max_fibers` (1024).
- **Opcodes** (`op.rs`): `Op` is `#[repr(u16)]`, and every variant has an explicit permanent number. The `define_ops!` macro generates the enum, `Op::ALL`, `from_u16`, `name()` and `shape()` from one table. The header comment in `op.rs` gives the ranges: 0x000-0x00F control, 0x010-0x01F constants/moves/select/globals/memory management, 0x020-0x03F i32, 0x040-0x05F i64, 0x060-0x07F plain loads/stores, 0x080-0x09F narrow loads/stores, 0x0A0-0x0BF f32, 0x0C0-0x0DF f64, 0x0E0-0x0FF width conversions, 0x100-0x11F conversions. The `hot_ops_are_one_byte` test checks that the common ops fit in one LEB byte. `Op::is_terminator` covers `ret`, `jmp`, `br_table` and `unreachable`.
- **Shape** (`op.rs`): the operand layout of each op (`D`, `DA`, `DAB`, `Select`, `Load`, `Store`, `ABC`, `Jmp`, `Br`, `Call`, `CallIndirect`, `Ret`, and others). The binary decoder, the verifier and the builder all dispatch on it.
- **OPCODES.md**: `opcodes_markdown()` (`op.rs`) renders the table. `cargo test -p efevm --test opcodes` rewrites `OPCODES.md` when its content differs. The `opcodes_md_lists_every_op` test checks that every mnemonic and hex code is present.
- **Inst** (`module.rs:26`): a fixed 16-byte `{ op, a, b, c: u32 }`. The field mapping is in the doc comment at `module.rs:8-24`. In short: `D` uses `a=d`; `DA` uses `a=d, b=a`; `DAB` uses `a=d, b, c`; `ConstI64`/`ConstF64` put the low 32 bits in `b` and the high 32 bits in `c`; `Select` uses `a=d, b=cond, c = ra | rb<<16`; `Load` uses `a=d, b=base, c=offset`; `Store` uses `a=src, b=base, c=offset`; `Jmp` uses `a=L`; `Br` uses `a=reg, b=L`; `BrTable` uses `a=reg, b=index into br_tables`; `Call` uses `a=func, b=base`; `CallIndirect` uses `a=type, b=reg, c=base`; `Ret` uses `a=base`. Unused fields must be 0, and the verifier rejects anything else (`NonZeroUnusedOperand`).
- **ModuleData vs Module** (`module.rs`): `ModuleData` is the plain, unverified form (types, imports, functions with `code` and `br_tables`, `table`, `memory`, `globals`, `exports`, `data`, `names`, `lines`). `Module` wraps it in an `Arc` and exists only after `verify::verify` has passed (`Module::new`). `Module::decode` is `binary::decode` followed by `Module::new`, and `export_func` / `export_global` look up exports by name.
- **Builders** (`builder.rs`): `ModuleBuilder::add_type` deduplicates function types. `import` must come before any function (otherwise `BuildError::ImportAfterFunction`). `declare_func` and `define` allow forward references and mutual recursion, and `add_func` does both at once. `FunctionBuilder::new(nregs)` has typed emitters (`op0`..`op3` check the shape, and `const_*`, `load`, `store`, `call`, `ret` and so on are direct). Labels come from `new_label()` and `bind(l)`, and are stored as label ids. `finish_unverified` resolves each id to an instruction index (`resolve`, `builder.rs:199`), and `finish` then verifies. The first builder error is kept and reported at finish. `loc(file, line, col)` records line entries, and `file(name)` interns file names.
- **Verifier** (`verify.rs`): `verify()` returns the first failure as `LoadError::Verify { func, inst, error }`. `VerifyError` has one variant per rule: index ranges (types, functions, globals, table, exports, names and lines), register numbers `< nregs`, label and `br_table` ranges, call and return windows (`base + max(P, R) <= nregs` for calls, `base + nresults <= nregs` for `ret`), `nregs >= params`, `global.set` only on mutable globals, 32-bit global initializers with no upper bits, memory `min <= max`, data segments inside the initial memory, a terminator as the last instruction (`MissingTerminator`), and zero unused operand fields. Duplicate export names are rejected too. The verifier is what makes "registers are untyped, memory is bounds-checked" safe (SPEC section 8).
- **Binary format** (`binary/`): `decode.rs` reads a header (`EFVM`, version `1`), then sections in strictly increasing id order from 1 to 11. Ids 128 and above are skipped as custom sections, and any other id is rejected. Each section's payload must be consumed exactly (`finish`, otherwise `SectionSizeMismatch`). Every vector count is checked against the bytes that remain before anything is allocated (`Reader::count`, `CountTooLarge`). Register operands must be at most `0xFFFF`. Unknown opcodes are reported with their number (`UnknownOpcode`). The functions and code counts must match (`FunctionCodeMismatch`). `leb.rs` implements the rule from SPEC section 9.1: a LEB is over-long if it has more than `ceil(bits/7)` bytes, or if the final byte sets bits the type cannot hold. `encode.rs` writes the same layout and omits empty sections, so `decode(encode(m)) == m`. Decode errors come back as `LoadError::Decode { offset, error }`.
- **Memory** (`memory.rs`): one `Vec<u8>` sized in 64 KiB pages. `Memory::new` returns `None` if `min > max` or the allocation fails. `range()` uses checked arithmetic, so an address past the end or an overflowing `addr + len` returns `Trap::OutOfBounds`. `load::<N>` and `store::<N>` take `base + off`. `copy` checks both ranges before moving and handles overlap. `grow` returns the old page count, or `None` on failure. The effective maximum is `min(module max, embedder cap)`, and it is applied in `Instance::new` (`instance.rs:87`).
- **Imports and Caller** (`imports.rs`): `Imports<H>` maps `(namespace, name)` to `(FuncType, HostFunc<H>)`. A host function has the form `Fn(&mut Caller<H>, &[u64], &mut [u64]) -> Result<HostOk, Trap>`. `Caller` gives access to `&mut H`, memory (`read`, `write`, `memory_mut`) and globals (`global`, `set_global`, which respects the mutable flag). `HostOk::Continue` continues execution, and `HostOk::Yield` writes the results and then suspends the fiber. A host function cannot call back into the VM (SPEC section 7).
- **Instance** (`instance.rs`): `Instance::new(&module, &imports, limits)` resolves every import by name and exact `FuncType` (`LinkError::MissingImport` or `ImportTypeMismatch`), allocates memory, copies data segments in, and initializes globals. `infos` holds one `FuncInfo { np, nr, nregs, canon }` per function index, and `canon` is a structural type id used for `call_indirect`. The `spawn(export, args)` and `spawn_func(index, args)` methods create a fiber with the arguments placed in `r0..`. Imports cannot be spawned (`ImportEntry`). `set_global` ignores the mutable flag, because it is the embedder's API.
- **Fibers** (`instance.rs`): a `FiberId { index, generation }` indexes a slot in `slots`. Freed slots go onto `free`, and their generation is bumped, so stale ids are rejected (`resume` returns `Trap::Host("invalid fiber")`). `FiberStatus` is `Ready` (spawned, or stopped by `OutOfBudget`), `Suspended` (after `yield` or a host yield), `Done`, or `Trapped(Trap)`. `resume(fiber, host, budget) -> Exit` and `resume_counted(...) -> (Exit, u64)` also return the number of instructions executed. `results(fiber)` is valid only for a `Done` fiber. When a fiber finishes or traps, its register stack is freed and only its results are kept. The fibers share memory and globals, but each has its own registers and call stack. The VM never switches fibers by itself.
- **Budget** (`interp.rs`, `run`): each instruction costs 1 unit, including `call`, host calls, `yield`, and an instruction that traps. When the budget reaches 0 before the next instruction, the loop saves `func`, `pc` and `fp` and returns `OutOfBudget`. A budget of 0 executes nothing.
- **Register stack and frames** (`interp.rs`): a `Stack` holds `regs: Vec<u64>` (all activations of one fiber, contiguous), `frames: Vec<Frame>`, the current `func`, `pc` and `fp`, and `results`. A `Frame { func, pc, fp, base }` records the return position, the caller's frame base, and `base`, the caller's window where the results go. Each activation's registers are `regs[fp..fp+size]`, with `size = max(nregs, params)`. Parameters start at `r0`, and the rest start at zero.
- **Calling convention** (`interp.rs`, `Op::Call`, `Op::Ret`): for a `call f, base`, the callee's new frame starts at the end of the caller's frame (`new_fp = fp + f.len()`). The `P` arguments are copied from `base` into `new_fp`. `ret base` copies `R` results from `base` into the caller's `base`, truncates `regs` back to the callee's `fp`, and restores the caller's `func`, `pc` and `fp` from the popped frame. Registers outside the window are untouched. The call depth is checked against `max_call_depth` and the total against `max_registers`, and both produce `Trap::StackOverflow`. For `call_indirect`, the table entry `g` gets the same frame setup, and the type check compares `canon` ids (`IndirectCallTypeMismatch`).
- **Host calls in the loop** (`interp.rs`): a call whose target index is below the import count builds a `Caller` over `host`, `memory`, `globals` and `gmut`. It passes the argument slice, writes results into a scratch buffer, and copies them into the window on success. `HostOk::Yield` then returns `Exit::Yield`, and `Err(t)` traps the fiber.
- **Traps and exits** (`trap.rs`): `Trap` has `OutOfBounds`, `DivideByZero`, `IntegerOverflow`, `InvalidConversion`, `Unreachable`, `StackOverflow`, `UndefinedElement`, `IndirectCallTypeMismatch` and `Host(String)`. `Exit` has `Done`, `Yield`, `OutOfBudget` and `Trap(Trap)`. A trapped fiber stays dead, but the instance remains usable (`instance.rs` test `host_yield_and_trap_and_link_errors`).
- **Integer and float semantics** (`interp.rs`): i32 results are written zero-extended. Shifts and rotates use the count modulo the width. `div_s` of `MIN / -1` traps with `IntegerOverflow`, and `rem_s` of `MIN % -1` is 0. The trapping truncations (`t_i32_f32_s` and so on) return `InvalidConversion` for NaN and `IntegerOverflow` when out of range. The saturating forms never trap. `fmin`/`fmax` return NaN if either input is NaN, and handle signed zeros. `nearest` uses `round_ties_even`.

## How to run
- Tests: `cargo test -p efevm`.
- Benchmark: `cargo run -p efevm --release --example bench`, with an optional iteration count argument. `examples/bench.rs` constants: default 100 000 000 iterations, `REPS = 5`, resume budget 10 000, target 10 ns per instruction.
- Regenerate the opcode table: `cargo test -p efevm --test opcodes`. This rewrites `OPCODES.md` if it differs.
- wasm check: `cargo check -p efevm --target wasm32-unknown-unknown -Z build-std=panic_abort,std`.

## Notes
- Diagnostics and host context: `Instance::trap_location` / `Instance::backtrace` give the trapping `(func, inst)` and the call stack of a trapped fiber (join them with the names and lines sections); `Caller::fiber()` tells a host function which fiber is calling.
- `src/instance.rs` has an `#[ignore]`d `bench_counting_loop` unit test. `examples/bench.rs` is the benchmark that is run in practice.
- `Instance::new` maps a data-segment write failure to `LinkError::MemoryTooLarge`. The verifier's `DataOutOfRange` check should make that path unreachable.
