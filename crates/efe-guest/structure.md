# efe-guest

`efe-guest` is the guest runtime for efescript mods written in Rust and compiled to `wasm32-unknown-unknown` (roadmap E7.4a; design in `crates/efescript/docs/e7.4-wasm-design.md`). Paired with bindings generated by `efescript api-export --rust`, it supplies [`Entity`], a `wasm32` `#[global_allocator]` and trapping `#[panic_handler]`, and the `provide!`, `provide_event!`, and `scratch!` macros that emit `efe_provide_*` exports, `efe_scratch`, and `efe.provide` custom-section records. On non-`wasm32` targets it builds as ordinary `std` code without the global allocator or panic handler so `cargo test --workspace` runs natively. It also ships the header-only C/C++ counterpart `include/efe_guest.h`.

## Public API & Macros
- **Types and traits (`entity.rs`, `record.rs`)**:
  - `Entity(pub u64)`: `#[repr(transparent)]` handle matching `hecs::Entity::to_bits` and the ABI `entity` (`i64`) type.
  - `ApiTy`, `Scalar` (`i32`, `i64`, `f32`, `f64`, `bool`, `Entity`), `Ret` (`()` or `T: Scalar`), `GuestStruct: Copy` (`const NAME: &'static str`, implemented by generated struct bindings).
  - `record::{KIND_FUNCTION, KIND_EVENT, KIND_SCRATCH}` and `const fn` size/byte builders `function_len`/`function`, `event_len`/`event`, `scratch_len`/`scratch`.
- **Guest macros (`lib.rs`)**:
  - `provide!`: requires `///` doc comments; supports scalar/`Entity` parameters, `str` (`&str`, traps on invalid UTF-8), `bytes` (`&[u8]`), and `&Name` (`Name: GuestStruct`, traps on null or misaligned pointer), plus `()` or scalar return values. Emits an `extern "C"` export named `efe_provide_<name>` and a `KIND_FUNCTION` record in `link_section = "efe.provide"` on `wasm32`. Parameters named `result` are rejected at compile time.
  - `provide_event!`: requires `///` doc comments; emits a `KIND_EVENT` record in `efe.provide` with no payload or `: PayloadStruct` (`<PayloadStruct as GuestStruct>::NAME`).
  - `scratch!($size)`: defines `#[unsafe(no_mangle)] pub static mut efe_scratch: Scratch<{ $size }>` (8-byte aligned) and emits a `KIND_SCRATCH` record (`size` in `1..=1_048_576`).

## Internals
- **Allocator (`heap.rs`, `lib.rs`)**: `Heap` obtains pages via `Memory::grow` (on `wasm32`, `core::arch::wasm32::memory_grow(0, pages)`), leaves address `0` unused (`cur` starts at `BASE_ALIGN = 16` when `base == 0`), and maintains one free list per power-of-two size class (`16` bytes and up). Blocks are neither split nor coalesced, allocations with alignment `> 16` bypass pooling and leak on `dealloc`, and linear memory never shrinks.
- **Record encoding (`record.rs`)**: Every record is `u8 kind, uleb32 body_len, body` evaluated in `const` context (`dry` pass for `LEN`, then write pass). Doc comment lines have one leading space stripped and are joined with `\n`, requiring at least one non-blank character.
- **C/C++ header (`include/efe_guest.h`)**: Mirrors the Rust macros (`EFE_PROVIDE`, `EFE_PROVIDE_EVENT`, `EFE_PROVIDE_EVENT_PAYLOAD`, `EFE_SCRATCH`, `EFE_TRAP`, parameter helpers `EFE_P`/`EFE_PS`, up to 8 parameters, names `< 128` bytes, docs `< 16384` bytes). Defining `EFE_GUEST_IMPLEMENTATION` in one C/C++ translation unit provides a 16-byte-aligned bump allocator (`efe_alloc` over `__heap_base` and `__builtin_wasm_memory_grow`, with `efe_free` as a no-op). Because clang/lld place `.custom_section.*` globals into wasm data segments rather than custom sections, `EFE_SECTION_PROVIDE` is `__attribute__((unused))` under `__wasm__`; C wasm mods supply their provides through `TranslateOptions::fallback` / `mod.toml` `[[provide]]`.
