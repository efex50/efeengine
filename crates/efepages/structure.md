# efepages

`efepages` is a sparse, paged byte memory crate. A `Page` holds a map from page index to a fixed-size byte buffer, so only pages that were actually written consume memory, and reads from untouched memory return zeros. The default page size is a compile-time constant (`PAGE_SIZE`, default 4096) generated by the helper proc-macro crate `page_size_macro`. It was originally used by the legacy `efescript` VM (which now uses linear memory in `efevm`), and remains in the workspace with no active dependents.

## Main concepts
- **`Page`** (`page/mod.rs:11-15`): fields `pagesize: usize` (private), `pub page: PageMap`, `max_pages: Option<usize>` (private, always `None` today). `PageMap` is `HashMap<usize, Vec<u8>, BuildHasherDefault<NoHashHasher<usize>>>`, keyed by page (sector) index.
- **Construction**: `Page::default()` uses `PAGE_SIZE`; `Page::new_with_custom_pagesize(n)` (`init.rs:9`) uses a custom page size, with `max_pages: None`.
- **Address mapping** (`funs.rs:188`, `get_vars`): for an address `start`, sector = `start / pagesize`, offset within the page = `start % pagesize`, and `end_sector` = `start.saturating_add(len - 1) / pagesize` (or `arena_sector` when `len == 0`).
- **Reads** (`funs.rs:115`, `read(start, len) -> Vec<u8>`): clamps the range at `usize::MAX` via `saturating_add`, splits it into per-page slices (`ReadPages`), copies present bytes, and fills absent pages with zeros. Nothing is allocated by a read.
- **Writes** (`funs.rs:27`, `write(start, Vec<u8>)`): clamps the range at `usize::MAX` via `saturating_add` (truncating `write` if `start + write.len()` would overflow `usize`), splits the data into per-page chunks (`get_writepages`, `funs.rs:62`), and writes into each sector. Absent pages are allocated via `create_new_page` as zero-filled buffers of `pagesize` bytes. Pages are never freed.
- **`PAGE_SIZE`** (`vars.rs`): produced at compile time by `page_size!()`. `page_size_macro` reads the environment variable `efepage_size` (default `"4096"`) and emits `pub const PAGE_SIZE:usize = ...;`. Because Cargo does not track `efepage_size` as an env dependency, a changed value only takes effect after rebuilding `efepages` (e.g. `cargo clean -p efepages`).
- **Allocation policy**: `efepages` does not allocate or manage virtual addresses itself; callers pass byte offsets directly.

```rust
use efepages::page::Page;

let mut mem = Page::default();          // PAGE_SIZE bytes per page
mem.write(20, vec![255; 500]);          // allocates the pages it touches
let bytes = mem.read(20, 500);          // Vec<u8> of length 500
assert_eq!(bytes.len(), 500);
let untouched = mem.read(1_000_000, 4); // zeros, nothing allocated
```

## Public API
- `efepages::vars::PAGE_SIZE: usize` - compile-time page size (4096 unless `efepage_size` is set at build time).
- `efepages::page::Page` - sparse paged memory (`#[derive(Debug)]`, `Default`).
- `efepages::page::PageMap` - `HashMap<usize, Vec<u8>, BuildHasherDefault<NoHashHasher<usize>>>` type alias using `NoHashHasher`.
- `Page::default()` - new empty memory with `PAGE_SIZE` pages.
- `Page::new_with_custom_pagesize(pagesize: usize) -> Page` - new empty memory with a custom page size.
- `Page::set_max_pages(&mut self)` - currently `todo!()` (panics).
- `Page::write(&mut self, start: usize, write: Vec<u8>)` - writes bytes at an address, allocating pages as needed.
- `Page::read(&self, start: usize, len: usize) -> Vec<u8>` - reads bytes; absent pages read as zeros.
- `pub page: PageMap` field - direct access to the underlying page map.

## Status and known gaps
- `set_max_pages` is `todo!()` (`crates/efepages/src/page/init.rs:14-16`); calling it panics.
- `create_new_page` has an inverted check (`init.rs:21`): it tests `max < self.page.len()` instead of `self.page.len() < max`. The `"Maximum pages reached"` panic at `init.rs:23` is unreachable today because `max_pages` is always `None`.
- `Page::new_with_custom_pagesize(0)` is accepted without validation and will divide by zero in `get_vars` on the first `read`/`write`.
- Clamping with `tail = start.saturating_add(len)` (`len = tail - start`) prevents `usize` overflow panics, but means a range reaching `usize::MAX` stops before byte `usize::MAX` itself (e.g. `read(usize::MAX, 1)` returns empty and `write(usize::MAX, vec![..])` is a no-op).
- No free / unmap of pages; allocated pages stay in `self.page` until dropped.
