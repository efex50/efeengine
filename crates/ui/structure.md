# efeengine-ui

The common UI API of the engine (design: `docs/ui/API.md`, sections 1 to 15; plan: `ui-roadmap.md`, Phase 1 retained layer; scripts and mods: section 9, `src/scripting.rs`; guide: `docs/ui/GUIDE.md`). A retained `UiTree` resource with a change journal, a style subset and themes, signals, bindings, the `UiBackend` trait, a headless backend and the `UiTest` helper. The web backend (DOM) is real (Phase 2); the native iced backend is in progress (Phase 0 spike done, the start of Phase 3); the fallback backend (`src/fallback`, feature `fallback`, phases F1 to F3) is built and tested, wired through core's `Draw2DOverlay` (`docs/ui/FALLBACK_NATIVE.md` section 9; `UiPlugin::fallback()`, automatic in SDL mode); no UI toolkit type appears in the API. The Elm-style view layer (section 16) is the `view` module, built on top of the public tree API. The engine-free model (tree, journal, styles, themes, css, signals, bindings, `El` and the reconciler, the headless checker) lives in the separate crate `efeui-core` (`crates/ui-core`); this crate is its engine adapter: backends, plugin, scripting, painters, `UiTest`, and the conversions of engine types (`TextureHandle` <-> `ImageId`, `InputCapture` <-> `UiCapture`, engine access in `BindCx`).

## Main concepts

### Tree (`tree.rs`, `node.rs`, `id.rs`)
- `WidgetId { index, generation }`: Copy, Hash, stale ids are rejected everywhere (`get` returns `None`, setters return `false`, `remove` is a no-op). `to_bits` / `from_bits` pack it into a `u64` for scripts.
- Roots are **layers**: `ui.layer(name, Layer)` makes a root container with key `name` (`Layer { z, modal, anchor, offset, window }`, helpers `Layer::fill(z)`, `centered`, `top_left`, ..., `.modal()`, `.offset(x, y)`, `.window(w)`; `ui.layer_in(window, name, layer)`; `layers_in(window)`, `layer_window`, `window_of`, `layer_windows`, `snapshot_changes`). A layer is shown in one window (0 = main); `z` and modal acting inside it; `docs/MULTI_WINDOW.md`. An existing name returns the same id and updates the data (`UiChange::Layer`). `layers()` lists them by z; `modal_active()` is true while a visible modal layer exists.
- Creation: `ui.column(parent)`, `row`, `container`, `scroll`, `text(parent, &str | String | Bind<String>)`, `button`, `checkbox`, `slider(parent, range, value)`, `text_input`, `image`, or `create(parent, NodeKind)` (panics on a stale parent) / `try_create` (returns `Result`). They return a `NodeRef` with chained setters (`.class`, `.classes`, `.key`, `.visible`, `.enabled`, `.hover_signals`, `.style`, every `Style` field as a method, `.placeholder`, `.max_len`, `.password`, `.step`) and `.id()`. `ui.node(id)` gives a `NodeRef` for an existing node.
- Setters on existing nodes (each writes one journal entry, none when nothing changes): `set_text`, `set_value(id, impl Into<UiValue>)` (slider clamped, text cut to `max_len`, wrong type returns `false`), `set_kind(id, NodeKind)` (same `KindTag` only), `edit_kind`, `set_image`, `set_visible`, `set_enabled`, `set_class`, `set_classes`, `add_class`, `remove_class`, `set_style`, `edit_style`, `style_mut(id)` (guard, one entry on drop), `move_to(id, parent, index)`, `remove(id)`, `remove_owner(&Owner)`, `set_theme`, `load_font`. `set_key` returns `Err(KeyTaken)`; the builder `.key` panics on a duplicate.
- Reads: `get`, `contains`, `len`, `iter`, `parent`, `children`, `kind`, `text_of`, `value`, `visible`, `enabled`, `is_shown` / `is_enabled` (include ancestors), `find(key)`, `key_of`, `owner_of`, `layer_of`, `layers`, `subtree`, `nodes_of(&Owner)`, `class_names`, `has_class`, `theme`, `resolve`.
- Owners: nodes get the tree's current owner (`set_owner`, `with_owner`; default `Owner::Game`). `Owner::from_engine_owner(engine.current_owner())` maps a plugin context. `remove_owner` removes every node of an owner with its subtrees (also foreign children under them).
- Class names are interned (`class_id`, `class_name`).

### Journal (`journal.rs`)
`UiChange { Created, Removed, Moved { id, parent, index }, Kind, Style, Classes, Visible, Enabled, HoverSignals, Layer, Theme, Font }`. `take_changes()` hands the frame's entries to the plugin and coalesces `Moved` to one entry per node with its final parent and index (valid against the final tree; backends place by final tree order). Coalescing the tree does: no property entry for a node created this frame (`Created` covers it); created and removed in the same frame leaves nothing; `Removed` is written for every node of the subtree, children first, and drops the node's earlier entries and `Moved` entries into it; a setter that changes nothing writes nothing. So a backend never sees an entry for an id that is gone, and `Created` is always before later entries of that id.

### Style and themes (`style.rs`, `theme.rs`)
`Style` is `Copy` with `Option` fields; `merge(&over)` / `overlaid(&over)` put set fields on top. `Theme { base, kinds, classes }` with `Theme::dark()` (the default), `Theme::empty()`. Resolution (`UiTree::resolve(id, WidgetState)` or `Theme::resolve`): `base`, kind normal, each class normal in order, inline style; then the state styles (hovered, pressed, focused, disabled; active ones only, later wins) of the kind and of each class on top of that, so a state style also beats the inline style (the literal reading of the design doc). `disabled` is added from the node's own or an ancestor's `enabled == false`.

### Signals (`signal.rs`)
`UiSignal { widget, key, owner, kind }`, `UiSignalKind { Click, Changed(UiValue), Submit(String), Focus(bool), Hover(bool) }`, `UiValue { Bool, F32, Text }`, `signal.key_kind()` -> `(&str, &UiSignalKind)`. `filter_signals(tree, raw)` is what the plugin runs on the backend's signals: drops stale, hidden, disabled, below-a-visible-modal-layer and ill-typed ones (`Focus(false)` is only dropped when stale) (and `Hover` without `.hover_signals()`), sanitizes `Changed` values and writes them into the tree without a journal entry, fills key and owner from the node. The result is put into the readable buffer of core's `Events<UiSignal>` (registered by the plugin) with `Ctx::send_batch_now` at `INPUT + 10`, so every later system of the same frame reads it with `cx.events::<UiSignal>()` or `cx.ui_signals()` (trait `UiCtxExt`, an iterator over the same events; collect it first if the loop needs `cx` mutably). They are dropped at the next frame's event update.

### Bindings (`bindings.rs`)
`Bind<T>` is a `Send + Sync` function `Fn(&BindCx) -> Option<T>`: `Bind::res(|s: &R| ..)`, `Bind::query::<Component>(entity, |c| ..)` (reads the world), `Bind::with(|cx: &BindCx| ..)` (resources, world, time). Register with `ui.bind_text / bind_value / bind_checked / bind_visible / bind_enabled / bind_class / bind_image`, or pass a `Bind<String>` to `ui.text(..)` / `ui.button(..)`. The registrations wait in the tree until the bindings system moves them into the `UiBindings` resource (`absorb`), which also drops the bindings of removed widgets. `evaluate` returns only the values that changed since last time; applying them is a normal tree change (journal entry only if the node really changed). A `None` result leaves the property alone. `evaluate` takes `&self` (last values behind a mutex per entry): the plugin borrows `UiBindings` in place instead of removing and reinserting it every frame, and only writes it (`absorb`, which moves the tree out of its slot for the call) on frames where the tree has new registrations or removed ids, so `res_changed::<UiBindings>()` is quiet otherwise.

### Backend and plugin (`backend.rs`, `headless.rs`, `plugin.rs`)
`UiBackend: 'static` (not `Send`): `init`, `input(&InputEvent) -> Filter` (no tree: a native backend keeps its own copy), `sync(tree, changes, theme, cx)`, `drain_signals`, `capture`, `resize`, and the native hooks with empty defaults `gpu_init(&Gpu)`, `gpu_resize(&Gpu)`, `render(&Gpu, &TextureView)`, `take_text_input() -> Option<Option<TextInputArea>>`, `take_cursor_icon() -> Option<CursorIcon>`, and `set_painters(&UiPainters)` (called once after `init`; backends that paint GPU views keep the handle). `Filter` is core's. `UiPlugin::new()` uses the web backend on wasm32, the iced backend on native when feature `iced` is on and the engine is not headless (`EngineConfig::headless`), else the headless backend (and inserts `HeadlessHandle`), `UiPlugin::with_backend(b)` any other, `.theme(t)` replaces the dark theme. The backend sits in an `Rc<RefCell<..>>` shared by an `InputFilter` (every raw event goes to `backend.input` before `InputState::apply`; `try_borrow_mut`, a busy backend passes), a `RenderOverlay` (`gpu_init` / `gpu_resize` / `render`) and four main-thread systems (`add_system`): `ui_resize` (PreUpdate, `INPUT + 5`: window resizes to `backend.resize`), `ui_signals` (PreUpdate, `INPUT + 10`: drain, `take_text_input` -> `cx.commands.set_text_input(_area)`, `take_cursor_icon` -> `cx.commands.set_cursor_icon`, filter, write back, `send_batch_now` the signals, `InputState::set_capture` = backend `capture()` OR visible modal layer OR input events `backend.input` answered `Filter::Captured` this frame: key and text count as keyboard, mouse, wheel and touch as pointer), `ui_bindings` (PostUpdate, `LATE + 10`, borrows `UiBindings` in place), `ui_sync` (PostUpdate, `LATE + 20`: `take_changes`, plus the image refresh: a texture replaced in `Textures` since it was last handed over adds the new image to `UiBackendCx.images` and a synthesized `UiChange::Kind` for every `Image` node showing it; `sync` only when the changes are not empty).
`HeadlessBackend` keeps no widgets: it records every change, checks consistency (created id new and alive with a live parent; removed id known and gone; other changes name a known live id; moved parent exists) and collects violations as strings (`HeadlessHandle::errors()`). `HeadlessHandle` also injects signals, sets the capture flag and reads the recorded journal and batch sizes.

### UiTest (`testing.rs`)
`UiTest::new(|engine| ..)` (headless engine, 60 Hz, `UiPlugin::new()`), `step(n)` (panics on journal errors), `click`, `set_value`, `set_checked`, `type_text`, `submit`, `focus`, `hover`, `signal`, `text(key)`, `value(key)`, `id(key)`, `ui()`, `ui_mut()`, `resource::<T>()`, `resource_mut::<T>()`, `capture()` (core's `InputState::capture()`), `changes()`, `backend()`, and the public `engine`. Helpers only queue a signal in the headless backend; the next `step` delivers it through the plugin's normal path.

### View layer (`view/`, API.md section 16)
- `El<Msg>` (`el.rs`): kind data, classes, inline `Style` (all setters chained through the same `style_fields!` macro as `NodeRef`), key, visible / enabled, children, and handlers `on_click(Msg)`, `on_change` / `on_toggle` / `on_input` / `on_submit` / `on_focus` (boxed `Fn + Send + Sync` closures), `map(f)`. Kind setters `.placeholder .max_len .password .step`. Constructors `text button button_with checkbox slider text_input image container row column scroll slot`; `.child(x)` / `.children(x)` take an `El` or any iterable of `El` (`IntoChildren`); macros `column![..]`, `row![..]` (`#[macro_export]`: `efeengine_ui::column`, import explicitly, std has a `column!` too).
- `UiView<Msg>` (`plugin.rs`): `new(name, Fn(&S) -> El)`, `with(name, Fn(&ViewCx) -> El)`, `.layer`, `.when(RunCondition)` (repeated calls OR), `.enabled`. Plugin `efeengine-ui/view/<name>`, depends on `efeengine-ui`, registers `Events<Msg>` and the `UiViews` resource (`set_enabled`, `is_enabled`, `toggle`). Nodes are owned by `Owner::Plugin(<plugin name>)`, the layer key is `<name>`.
- Systems per view: `ui_view_messages` (PreUpdate, `INPUT + 11`: signals of widgets in the handler table become `Msg` via `send_batch_now`, and mark the view dirty so it runs this frame under `.when`) and `ui_view` (PostUpdate, `LATE + 11`, after bindings at `LATE + 10` and before sync at `LATE + 20`: enabled check, condition, build the whole `El`, `validate` duplicate keys, then `tree.with_owner(..)` { layer, visible, `reconcile_root` }, replace the handler table).
- `reconcile.rs`: diffs the `El` against the tree (not a previous `El`). Per parent: keyed children match the node with the full key (parent must be the same, else that node is removed and recreated), unkeyed ones match an unkeyed child at the same index; kind mismatch or leftovers are removed (before creating, so keys are free); then in order create / `move_to` when the child at index i differs / update kind data, classes, style, visible, enabled. Slots are updated but their children are not visited. Key scheme: `<view>/<keys of keyed ancestors>/<own key>`, unkeyed elements add nothing.
- Frame order: INPUT+10 signals, INPUT+11 messages, Update (game reads `Events<Msg>`), LATE+10 bindings, LATE+11 views, LATE+20 sync.

### Fonts
`UiTree::load_font(name, bytes)` registers a `FontId` and journals `Font(id)`; `font`, `font_by_name`, `fonts`. No font file is bundled yet (the native default font and `THIRD_PARTY_NOTICES.md` entry come with the native backend).

### Web backend (`web.rs`, `dom_plan.rs`, `css.rs`; API.md sections 5, 6, 10, 12)
`UiPlugin::new()` uses `WebBackend` on wasm32 (`UiPlugin::headless()` always headless). Layer element: startup config `uiLayerId` (default `ui`, created in the canvas's parent if missing; marked `data-efui-layer`). One element per node (`data-efui-id` = `WidgetId::to_bits`), inline style = resolved normal style diffed against the last written declarations, `<style id="efui-base">` and `<style id="efui-theme">` (hover, active, focus, disabled with `!important`) in `<head>`. Journal applied against the final tree: `Created` builds the element, parents named by `Created` / `Moved` get their DOM children ordered like `tree.children`. Delegated listeners on the layer element (kept in the backend, removed on drop) produce the signals; capture from pointerover / pointerout plus `:hover` and from `document.activeElement`. Modal layers get a transparent backdrop element. GPU views: see the GPU views section (web). `UiBackendCx.images` carries RGBA for `Image` nodes (drawn once into a canvas). Core side: `web_impls::is_editable_target` also ignores key / composition events from inside `[data-efui-layer]`.

### Native backend (`native/`, iced; roadmap Phase 0 and Phase 3)
- Built on `iced_wgpu` (features `image`) + `iced_runtime::UserInterface` + `iced_widget` + `iced_core` only (no `iced_winit`, no winit). The engine owns window, surface and loop; the backend renders into the engine's target view with `LoadOp::Load` through `Renderer::present`.
- `gpu_init`: builds `iced_wgpu::Engine` / `Renderer` from the engine's `Gpu` (device, queue, surface format, adapter).
- `sync`: rebuilds the whole `Model` (visible nodes only, five resolved styles per node: normal, hovered, pressed, focused, disabled; unset `bold`, `font`, `text_color`, `font_size`, `text_align` inherited from the parent like CSS) when the journal is not empty, and takes new images (`cx.images` -> `Assets`, `image::Handle::from_rgba`) and fonts (`UiChange::Font` -> iced's global font system; the family name is read from the font file). `Assets` also loads the bundled Inter Regular and Bold (SIL OFL) once; `Style.font` is the family by registered name, `bold` the bold weight, the default family is Inter.
- Identity: iced matches widget state by tree position, so every row, column and the layer stack are wrapped in `keyed::Keyed`, which keeps the child keys (node id bits; spacers get keys from `u64::MAX` down) next to the state and permutes the child trees in `diff` before iced's positional diff: focus, caret, selection and scroll offset follow the node across layer insertions and reorders (tested on the GPU: `tests/native_gpu.rs`).
- `input` (from the engine's input filter): `convert::Converter` maps mouse, wheel, touch, key (physical key to iced's `Physical::Code`, `Unknown` to `Unidentified`; modifiers become `ModifiersChanged`), `Text` (-> `InputMethod::Commit`), `TextEditing` (-> `Preedit`), focus; positions are divided by the scale factor. One `UserInterface` build + `update` per event, messages applied to the model and turned into signals right away (typing and dragging never wait for the tree), `max_len` is enforced on our side. Tab / Shift+Tab (when the model has text inputs) and Escape (when one has focus) run iced's `focus_next` / `focus_previous` / `unfocus` operations (followed through their `Chain`) and are captured. Clipboard: the update's `Clipboard` requests are served with `efeengine_core::clipboard` (write -> `set_clipboard_text`; read -> a follow-up `Event::Clipboard(Read)`). Verdict `Captured` for a pointer event when iced captured it or the pointer is over a blocking node (`mouse_area` enter / exit messages around every node that is not a plain Container / Text, and the backdrop of a modal layer), for a key / text event when iced captured it, it was a navigation key, a text input has focus (found with a focus `Operation` after every update) or a modal layer is visible.
- Text focus: when the focus changes the backend queues the text-input request (`SetTextInput(true)` + area from iced's input-method cursor rectangle in logical px; `false` on blur); the plugin issues the commands in `ui_signals`. `Focus(bool)` signals come from the same probe. The mouse cursor: the `mouse_interaction` of every update is mapped to a `CursorIcon` and queued only when it changes.
- `render` (idle cost): a frame is *active* when the model, an input event, a window / scale change or a redraw request (`window::RedrawRequest` of the last update: `NextFrame`, or `At(t)` for the caret blink) asks for it: then it builds, lays out, updates with `RedrawRequested`, draws and presents. Otherwise it only presents the primitives the renderer still holds from the last active frame (the engine cleared the target, so the overlay must be composited again, but nothing is rebuilt, laid out or drawn; offscreen check: identical pixels). Nothing happens while no layer is shown. `EFE_UI_STATS=1` logs active and idle averages every 300 frames.
- `view.rs`: layers become a keyed `stack` ordered by z (anchor -> alignment, offset -> padding, modal -> `opaque` backdrop), nodes become container / row / column / text / button / checkbox / slider / text_input / scrollable / image / space. Style mapping is documented at the top of the file (Auto = iced `Length::Fit`, `Fill` / `Portion` / stretch only when the parent's size on that axis is definite, min / max = `Length::min` / `max`, justify = `Fill` spacers when the main size is definite, opacity folded into colours, state styles through iced's status closures, button / checkbox / slider / text input only; focus style only for text inputs). Why not `Fill` in an auto-sized parent: iced merges lengths with "Fill wins over Fit", so a stretched child made its auto-sized parent fill the layer (the "glued layers, tall button" bug); `Fluid(Max)` made text take all the space.
- `offscreen.rs`: `render_offscreen(tree, images, size, scale, background, painters)` draws a tree with its own wgpu device (Rgba8UnormSrgb) and reads the pixels back (`Screenshot::png()` has a tiny PNG encoder); `render_offscreen_represented` presents the same drawn frame again. Used by the `#[ignore]`d GPU tests (`examples/ui_demo/tests/native_screenshot.rs`, `crates/ui/tests/native_gpu.rs`).

## Not done yet
- Web: fonts (`UiChange::Font`; being added separately), no IME work beyond the browser's own, no browser test automation (checked by hand with `examples/ui_demo`).
- Scripts: no GPU views, no arbitrary style fields (a fixed list of setters plus classes), no moving nodes between parents, no per-module filtering of the broadcast `ui.signal` event (the handle names the owner).
- Native backend: IME preedit drawing (the preedit reaches iced's editor, the OS popup placement works through `SetTextInputArea`), checkbox / slider / button focus style and tab stops (iced does not make them focusable), subtree `opacity`, stretch to the widest sibling in an auto-sized parent, a mouse cursor reset when the pointer leaves the UI is `Default` (it also overrides a game's own cursor), no Inter subset (two TTFs, 832 KB). Differences are listed in `docs/ui/API.md` ("Per-backend notes").
- The fallback native backend.
- View layer: moves across parents recreate the node; reorder uses one `move_to` per out-of-place child (no longest-increasing-subsequence minimization); no `hover_signals` on `El`.

## Scripts and mods (`scripting.rs`, API.md section 9, GUIDE.md section 6)

- Registered by `UiPlugin::build` (`scripting::register`, needs `Engine::api_open()`): namespace `ui` (owner `efeengine-ui`), struct `UiSignal` (16 bytes: `widget: i64`, `kind: u32`, `value: f32`), event `ui.signal`, about 35 host functions. Closures capture one `Arc<Mutex<Inner>>`; the same handle is the `UiScripts` resource.
- Host functions never touch the tree (lanes run in parallel on a snapshot). Per module (by `ModuleId`) `Inner` keeps a table of entries `{ widget: Option<WidgetId>, tag, own, mount, cache }`, keys and mounts; a call validates the handle (`lookup`: the module part must be the caller, the entry must exist, a mount is refused when modifying), updates the cache (text, bool, f32, so `get_text` / `value` / `checked` answer at once) and pushes an `Op` with `(module id, sequence)`.
- Systems: `ui_script_signals` (PreUpdate, `INPUT + 12`: `Events<UiSignal>` to `ScriptEvent`s for every table entry that points at the widget, kind and value as in the guide, `send_batch_now`) and `ui_scripts_apply` (PostUpdate, `LATE + 15`: drop the state of unloaded modules with `remove_owner`, sort the ops by `(module, sequence)`, apply each with `tree.with_owner(owner, ..)`, forget entries whose node is gone, refresh the exposed mount ids and, while a trusted script exists, the key snapshot `find` reads).
- Core support: `ScriptHost::is_mod(id)` (grant-limited module), `ScriptHost::current_module` / `module_name` (existing).
- Tested in `tests/scripts.rs` with `.efa` modules compiled in memory (`LoadInput::Folder` and `LoadInput::Efa`).

## GPU views (API.md section 17)

- Node `NodeKind::GpuView { painter, pointer }`, tag `KindTag::GpuView` (`gpu-view`, DOM tag `canvas`), builders `UiTree::gpu_view(parent, name)` / `NodeRef::pointer_signals()`, view layer `gpu_view(name).on_pointer(|PointerEvent| Msg)`. Signal `UiSignalKind::Pointer { pos, buttons, wheel }` (struct `PointerEvent` with `LEFT/RIGHT/MIDDLE` masks); `filter_signals` drops it for anything but a GpuView with `pointer`. `UiTest::pointer(key, pos, buttons)`.
- `painter.rs`: `UiPainters` is an `Rc<RefCell<HashMap<Arc<str>, Box<dyn UiPainter>>>>` handle (main thread). `EngineUiExt::add_ui_painter` / `ui_painters()` live in a thread-local table keyed by an engine resource (`PaintersKey`, which is `Send + Sync`), created lazily, so registering before or after `UiPlugin` works; `UiPlugin::build` passes the handle to `backend.set_painters`. Headless ignores it (never paints).
- iced (`native/gpuview.rs`): the node becomes `iced_widget::shader(ViewProgram)`. Painters cannot live in iced's `Send + Sync` primitives, so painting is split around `present`: `ui.draw` records requests (node, painter, logical bounds) through `Program::draw`; `ViewPainter::paint` (before `present`; also on idle frames, so views animate) creates / resizes one offscreen texture per view (physical size = round(bounds * scale), format = always `Rgba8UnormSrgb` (`VIEW_FORMAT`; painters output linear), usages RENDER_ATTACHMENT | TEXTURE_BINDING | COPY_SRC | COPY_DST), calls `resize` on a new size / scale / format, then `paint`, one command buffer for all views; `ViewPrimitive` composites the texture with a fullscreen triangle (iced sets viewport = bounds, scissor = clip), premultiplied blend, in iced layer order (the composite shader writes the sampled linear value for an sRGB iced target, or sRGB-encodes it for a non-sRGB one). Zero-size views are skipped; a missing painter logs one warning and the view is transparent; textures of views no longer drawn are dropped. Pointer: the widget's `update` publishes `Msg::Pointer` (move inside, press, release, wheel; press / release / wheel over the view are captured); the wrapper `mouse_area` gives hover and capture like any blocking node. `render_offscreen*` take `Option<&UiPainters>` and paint in `Rgba8UnormSrgb`.
- Web (`web.rs`): each `GpuView` entry has a `GpuViewState { painter, surface: Option<Result<ExtraSurface,()>>, seen }`; `set_painters` keeps the `UiPainters` handle. an `Auto` GpuView width/height is pinned to `0px` by `dom_plan::gpu_view_auto_decls` (empty, never painted, like native). `UiBackend::render` (the engine's render overlay, also on wasm) calls `paint_gpu_views`: for each entry, physical size = round(`clientWidth/clientHeight` * `devicePixelRatio`) (a hidden node is `display: none`, so size 0 and skipped), missing painter = one `console.warn` per name, `ExtraSurface::for_canvas` created lazily, `surface.resize` on size / scale change, `painter.resize` on size / scale / format change, then `acquire` -> `ViewTarget` -> own encoder -> `paint` -> submit -> `present`. `render` never touches the main target. The surface is dropped with the entry (`remove`). Pointer: delegated `pointerdown/up/move` and `wheel` listeners on the layer element map GpuView targets to `UiSignalKind::Pointer` (`pos` = offsetX/offsetY, `buttons` = DOM `MouseEvent.buttons & 7`, which equals `PointerEvent::LEFT/RIGHT/MIDDLE`; `wheel` = -deltaX/-deltaY to match iced, raw units); a press calls `setPointerCapture` so release and drags arrive outside the view; pointer-enabled canvases get `touch-action: none`, wheel is `preventDefault`ed. Pointer over the canvas counts as UI capture through the generic pointerover flag.
